## 问题、约束与非目标

当前主流程只有 brief 输入和完整稿后的批准，旧审阅页未接入主流程。用户需要先看建议、明确关键业务选择再形成完整稿。状态由同一 Mastra Run 持有，回答与批准均绑定版本；保持旧 Studio 输入兼容。不增加认证、附件理解、风格图库、跨实例并发或独立流程数据库。

## 决策与实施边界

结论：适配。用户已明确授权上述闭环；新增可选 guidedIntake，默认关闭。新页面在主 Run 内开启澄清，原生子 Workflow 用 dountil 保存多轮方案与人工回答。模型输出经 Zod 校验；服务端只恢复允许的澄清和产品确认步骤，恢复前校验当前 payload/hash 与答案，非法输入不得消耗暂停点。推荐项不预先成为回答。前端只持有未提交输入，确认事实与版本归 LibSQL 快照。HTTP Adapter 负责协议转换，纯函数负责答案校验，复用现有四产品角色生成完整稿，不增加 Agent 或依赖。

受影响路径：practices/mastra/src/intake/、src/mastra/workflows/、src/mastra/app.ts、web/src 与 vite.config.ts、tests、实践文档。历史 Run 不迁移；回退可关闭 guidedIntake 并使用 Studio。服务仅本机，审阅人仍是本地声明；进程内互斥不声明分布式锁。维护责任归实践维护者。

## 提交反馈与需求分析恢复

真实第二轮暴露直接 JSON.parse 自由文本的缺陷；改用已锁定 Mastra Agent.generate 的 structuredOutput/schema 和 object，不增加解析器或依赖。需求分析失败仅在明确叶节点、已保存 Delivery/Intake 和相同模型模式时允许原生 timeTravel；重试令牌绑定 Run、失败阶段和保存的回答，不适用于开发或外部副作用。新增底部持续可见请求反馈、等待计时、操作按钮状态、成功/错误提示与运行态只读轮询；不伪造百分比或自动重发写请求。需要专项验证失败后历史和轮次保留，以及长请求下可见反馈。

## 2026-11-08 区分 HTTP 超时与执行失败

锁定版本的 Mastra dev 生成服务默认使用 Hono timeout(server.timeout ?? 180000)。长模型生成期间提交请求可先收到504，而 Run 仍为running；这不是模型上游524，也不是Runtime终态。现保持后端执行边界不变，前端写请求异常后只回读原生Run：running进入只读观察，读取暂不可达标为状态待确认并持续轮询，failed才展示失败恢复。禁止自动重发写请求，不用扩大HTTP等待时间掩盖状态不一致；纯函数回归覆盖504后running、终态及读失败。修复仅前端，不重启正在运行的模型任务。

## 2026-11-08 写作上游524修复

实际错误快照证据：产品写作约456秒后返回Cloudflare 524；最后一次请求为非流式、消息约81687字符、未显式设置输出上限。输入包括完整四轮确认与三个前序产物，不能通过丢弃确认事实解决。采用当前已安装Mastra原生Agent.stream/getFullOutput，仅调整live写作传输；其他角色与固定模式保持兼容。选择流式而非仅放宽页面HTTP超时（不能改变上游524），也不新增自研流协议或立即更换供应商。

写作显式maxRetries=0，避免长请求隐式重试叠加；单步180秒、总360秒，最多16000输出token。预算是执行边界，不是交付完成证据；error、截断或异常结束均不得发布部分文稿。维护责任归Mastra实践维护者。若真实完整文稿仍超过单次预算，重评按文档章节生成并持久化的方案，不以无限增大超时替代分片。当前修复不声称可以消除所有模型入口故障。

写作修复验收：同一真实Run的写作以129.7秒、7个模型步骤完成并进入review-product，生成7036字符草稿，保留四轮回答及前三角色。浏览器回读核对，未提交产品批准。实际协议专项4/4，全量180/180、类型检查与前端构建通过；真实单例不能替代全部产品质量或供应商可靠性验证。524定义的官方依据：https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/ 。

## 2026-11-08 仓库关联与业务化范围选择

用户要求通俗文案、基于已明确仓库的细粒度选择和自动关联。复用现有经origin校验的HRM根目录，新增只读源码清单，绑定当前分支、提交和文件内容散列；不接收浏览器指定宿主路径、不执行仓库命令、不读取.env、隐藏目录或符号链接。UI使用独立项目范围组件，替换底层文件快照表单，自动关联HRM、按前端/后端/数据库/工程筛选文件，并展示真实package.json中的check/build/smoke。

## 2026-11-10 取消澄清总轮数限制（接受）

用户明确要求落实取消澄清总轮数上限。适配既有 Mastra dountil/suspend/resume：移除 intake round/history 的 max(4)、第四轮 refine 拒绝及前端禁用和提示，每轮八题与显式 finalize 保留。沿用原生快照和散列算法，旧快照无需迁移；运行中的节点不主动重放，部署加载新代码后生效。不新增澄清累计费用/调用预算或追加额度审批。

选择这一局部适配而非新增预算状态机或另起流程：轮数不能证明业务成熟，已有原生恢复足以保存回答；新状态机增加无业务依据的人工关口。应用维护者承担历史增长和真实模型质量的后续验证。资源保护、上下文压缩与业务成熟度分别处理，不因达到资源边界删需求或成稿。产品成熟度自动判定与写作后审查仍未实现。
