# 接通 Mastra 主流程的交互式需求澄清

- 状态：接受
- 日期：2026-11-07
- 负责人：Mastra 实践维护者
- 所属区域：渠道与体验层（独立实践）
- 关联需求：用户明确授权方案摘要、关键问题卡片、回答修订与产品稿确认闭环
- 关联 OpenSpec：不改变探索主线稳定契约；实践契约见 practices/mastra/guided-intake.md
- 替代记录：无；扩展完整产研生命周期记录

## 问题、约束与非目标

当前主流程只有 brief 输入和完整稿后的批准，旧审阅页未接入主流程。用户需要先看建议、明确关键业务选择再形成完整稿。状态由同一 Mastra Run 持有，回答与批准均绑定版本；保持旧 Studio 输入兼容。不增加认证、附件理解、风格图库、跨实例并发或独立流程数据库。

## 候选与证据

| 路线 | 候选 | 结论 |
| --- | --- | --- |
| 成熟一体化 | Mastra Studio 原生 Workflow 表单 | 可调试暂停，但不能提供面向业务的问题卡片与文稿阅读体验 |
| 轻量组合 | 已锁定 Mastra core 1.81.0 + React 19.3.1 + 现有安全 Markdown | 适配；复用原生持久化、暂停恢复和页面基础 |
| 最小自研 | 浏览器状态机加独立需求记录 | 不采用；重复拥有流程状态，刷新恢复及版本一致性成本高 |

证据：src/mastra/app.ts、workflows/product-development.ts、web/src；[官方暂停恢复说明](https://mastra.ai/docs/workflows/suspend-and-resume)。本地已锁定 API 和既有原生恢复回归是实施依据，不将最新文档视为当前版本运行证明。

## 决策与实施边界

结论：适配。用户已明确授权上述闭环；新增可选 guidedIntake，默认关闭。新页面在主 Run 内开启澄清，原生子 Workflow 用 dountil 保存多轮方案与人工回答。模型输出经 Zod 校验；服务端只恢复允许的澄清和产品确认步骤，恢复前校验当前 payload/hash 与答案，非法输入不得消耗暂停点。推荐项不预先成为回答。前端只持有未提交输入，确认事实与版本归 LibSQL 快照。HTTP Adapter 负责协议转换，纯函数负责答案校验，复用现有四产品角色生成完整稿，不增加 Agent 或依赖。

受影响路径：practices/mastra/src/intake/、src/mastra/workflows/、src/mastra/app.ts、web/src 与 vite.config.ts、tests、实践文档。历史 Run 不迁移；回退可关闭 guidedIntake 并使用 Studio。服务仅本机，审阅人仍是本地声明；进程内互斥不声明分布式锁。维护责任归实践维护者。

## 验收计划

- 原生暂停、回答、修订、完整稿批准与重开恢复；缺失必答、旧 hash、错误步骤、重复提交与模式变化不能推进。
- 类型检查、相关原生/HTTP 回归、前端构建、OpenSpec strict 和 diff 检查。
- 真实模型问题质量、跨实例、生成中崩溃与多人权限保留待验；不使用 fixture 证明业务质量。

## 风险、退出与重评

模型可能漏问或产出无效 JSON，后者明确失败，不降级成伪确认；人工最终审核继续保留。多轮上限限制成本，上限后仍可完成回答或结束并另起，不自动批准。模型质量、多人使用或跨实例部署成为需求时重评结构化生成、认证与协调。前端可替换，保留原生 Run 与 CLI/Studio 读取能力。

## 2026-11-07 业务前端边界修正

用户明确要求全部人工确认留在前端，并验证交互友好和向下推进。扩展既有 HTTP Adapter，为主流程已登记人工关口提供中文业务表单、只读审批材料及版本绑定，不要求跳转 Studio 或填写恢复 JSON。项目范围采用文件快照编辑/本地文件选择，检查与可写集合由原有 projectSchema 校验。开发、测试、发布与回执沿用现有 resumeSchema，前端表单由服务端白名单描述投影；版本令牌绑定完整暂停路径与材料，客户端不能指定恢复步骤。原生节点继续负责执行身份、候选与语义门禁，HTTP 在 resume 前校验表单、版本和可验证的引用。不增加命令、任意目录读取、CI/CD执行或认证权限。业务确认可操作不等于真实部署自动执行；外部发布、健康和回滚保留人工回执。

验收补充：从产品稿在页面继续到范围授权、开发方案、测试及发布关口；浏览器核对必填、材料阅读、二次确认和提交后关口变化；旧版本/非法字段不能消耗暂停点。真实业务模型质量、源仓库自动扫描和全栈仓库执行仍不在本次保证。

业务前端补验：全套170/170、补齐回滚后的专项5/5、类型检查、前端构建、OpenSpec strict 1/1 通过。浏览器实际填写快照与权限并进入开发批准，批准后进入测试确认；730px宽度无横向溢出。引用选择和绑定值预填只复用已保存事实，批准/实际结果不预选。质量输入校验从原节点抽为共用纯函数，HTTP和原节点复用，保留原有门禁语义。维护与未验边界沿用上文。
