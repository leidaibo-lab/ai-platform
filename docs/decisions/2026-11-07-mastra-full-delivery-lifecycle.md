## 问题与约束

当前单入口只包含产品与开发，遗漏测试及部署。目标是保持一个原生 Run，主链明确展示产品、开发、测试、部署、最终交付，角色内部独立展开。开发自检不能冒充独立测试，发布方案不能冒充已部署。用户“不用测试”约束本轮实现时不运行测试，不删除测试节点。没有指定远程环境、CI 或凭据，因此本次不触发真实发布，也不引入任意命令/网络权限。

## 候选与证据

| 路线 | 证据与选择 |
| --- | --- |
| GitHub Actions 等一体化 CI/CD | 官方 environments 支持发布保护与审批（https://docs.github.com/en/actions/concepts/workflows-and-actions/deployment-environments）；未指定仓库、环境、工作流与凭据，本轮不直接接管远程执行 |
| Mastra 原生嵌套 Workflow + 固定检查 Adapter + 人工外部回执 | 锁定 @mastra/core 1.81.0 的 Workflow、dountil、getInitData、suspend/resume 可组合；采用，保留角色图及证据事实，不新增通用引擎 |
| 自建 QA/发布调度与数据库 | 重复原生持久化及 CI 能力，不采用；自有代码仅适配版本绑定、质量判定、修复路由与外部执行回执 |

实施依据包括已安装 `workflows/workflow.d.ts`、执行引擎源码及官方 https://mastra.ai/docs/workflows/control-flow。候选发现不等于当前环境实际使用 GitHub Actions。

## 决策与数据边界

结论：**适配**原生 Workflow。维持唯一 Studio 入口和现有产品/开发展开，追加 `testing`、`deployment` 子 Workflow 和最终交付步骤。测试含独立测试计划 Agent、人工用例/覆盖确认、登记套件实际执行、质量确认、缺陷返工及回归。测试 Agent 仅读当前候选及已批准需求；不自动授予新命令或修改既有检查文件。自动用例绑定登记套件结果，人工用例逐项留存结果与依据；固定套件映射不等于自动证明全部业务覆盖。

测试反馈携带具体发现及责任路由。测试缺陷映射为不可变评估报告，交给现有开发门、任务依赖图和返工预算处理；保留 QA 人工记录作为来源，不能丢失旧研发交付/测试历史。修复后重走开发自检/评审和测试；业务/完整性问题停止或要求澄清。

部署含方案 Agent、环境/制品/回滚/健康检查范围审批、外部执行回执、健康结果及失败回滚。没有远程 Adapter 时，`execute-release-externally` 是明确的原生暂停点，等待人工提交外部 CI/部署系统的结果；不执行模型文本中的命令，也不自动请求任意 URL。所有回执标记 `local-human-report`，不宣称远程机器验证；本地审阅人不是认证身份。缺少回执、健康失败或版本不匹配均不得形成成功终态。实际发布仍须在选择的外部平台授权。

核心数据为版本化生命周期状态、每轮 QA 计划/检查/逐项结果/质量审阅、绑定源码散列的发布范围、执行及健康/回滚回执。原生 LibSQLStore 持有流程事实，候选文件仍属运行目录；步骤返回新快照。设计模式为原生 Pipeline、角色工厂与受限执行 Adapter；不创建另一套运行状态库。

## 实施、兼容与维护

受影响：`src/delivery/` 生命周期契约与测试/部署角色、`development-v2.ts` 的原状态继续入口、统一 Workflow、Studio Agent 注册、README 与决策索引。无依赖升级、无新增密钥或远程服务配置。旧 Run 的图结构变化后不承诺透明跨版本续跑；保留历史数据，新的全链路使用新 Run。退出时保留生命周期记录并替换部署回执 Adapter；不将人工结果转换为机器验证记录。

维护者负责质量门、来源绑定、反馈预算及回执 schema。需要自动 CI/CD、浏览器 E2E、新测试工具、认证、多租户或跨实例恢复时重新选型，并在配置具体环境后验证；不由本轮自然扩权。
