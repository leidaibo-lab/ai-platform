# Runtime 智能默认操作路由采用结构化意图分类

- 负责人：AI 应用基础平台维护者
- 所属区域：Agent Runtime
- 关联需求：默认由平台判断对话、文生图或单图编辑，减少用户发送前的模式选择
- 关联 OpenSpec：`openspec/changes/add-smart-operation-routing/`
- 替代记录：[`2026-08-15-runtime-context-aware-operation-routing.md`](./2026-08-15-runtime-context-aware-operation-routing.md)；本记录保留首版“当前附件约束候选 + 结构化分类”的历史依据

> 2026-08-15：本记录只覆盖当前输入和当前附件，无法处理无附件的会话指代、活动图片继承和历史证据校验。后续实现与验收以替代记录为准；显式 operation 仍保留为 API 兼容、历史图片操作和 Run 恢复边界。

## 问题

当前 Demo 要求用户在“对话 / 生图 / 图生图”中先做三选一，再输入自然语言。这个选择把平台已经掌握的附件类型、模型能力和意图判断责任转嫁给用户：上传一张图并说“保留人物，把背景改成夜景”时，用户仍需理解“图生图”的内部术语；切错模式则在模型调用前失败或执行错误能力。

目标用户应默认只提交问题、指令和附件。Runtime 根据受控附件事实和结构化意图选择真实 `operation`，并让低置信度判断保持无图片副作用。成功证据是：附件矩阵不可被分类模型越权；图片生成或编辑只有在置信度不低于 `0.85` 时才自动执行；分类子截止时间耗尽或其他非取消失败安全回退对话；Run 最终保存可审计、可幂等重放的真实 operation。

## 约束与非目标

### 必须满足

- 所有分类与业务执行继续经过 Agent Runtime 和 GatewayClient；浏览器不得直接调用分类模型或 provider。
- 附件类型、数量、会话所有权和资产状态由 Runtime 确定，是不可被模型输出覆盖的硬约束。
- 自动路由不得因低置信度、结构化输出失败、分类子截止时间耗尽或其他非取消分类调用失败触发图片生成/编辑副作用。
- `operation=auto` 不接受浏览器指定模型；Runtime 按解析后的真实 operation 使用服务端操作级默认别名。
- Run 持久化解析后的 `conversation.chat`、`image.generate` 或 `image.edit`，不把 `auto` 当作执行 operation，也不持久化 provider 原始分类文本。
- 幂等重放和显式恢复不得重新分类，避免同一用户输入在不同时间改变 operation 或重复图片费用。

### 本次不解决

- 多图编辑、远程图片导入编辑、文档生成图片、遮罩或局部重绘。
- 通用多 Agent 路由器、可视化工作流、动态工具规划或跨场景业务编排。
- 由分类模型选择真实 provider 模型、价格、尺寸或任意图片参数。
- 对分类置信度做线上学习、个性化校准或自动调整阈值。

| 候选 | 路线 | 覆盖范围 | 关键优势 | 关键缺口或风险 | 证据 |
| --- | --- | --- | --- | --- | --- |

本次没有引入成熟一体化路由/工作流产品。检索范围覆盖现有 Runtime、AI SDK Core 结构化输出和通用工作流边界；当前仅有三个稳定 operation，外部编排系统会同时引入状态、工作流和供应商生命周期，明显超出这一小型分类问题，也会与 Runtime 的 Run 事实所有权重叠。

## 淘汰条件

- 分类或模型输出可以绕过附件矩阵，选择输入不满足的图片操作。
- 低于 `0.85` 的图片意图会产生图片调用、资产或费用。
- 浏览器拥有分类 Prompt、阈值、真实模型名或 operation 最终判定权。
- 同一 requestId 重放、`retry`、`regenerate` 或 `continue` 会重新分类。
- 数据库只保存 `auto` 或 provider 原始分类正文，无法还原实际执行 operation。

## 决策

- 结论：适配
- 选择方案：Runtime 使用锁定 AI SDK Core `Output.object` 做有界结构化意图分类，并由确定性附件策略约束候选 operation。
- 决策依据：分类属于 Agent Runtime 的任务路由职责；SDK 已具备结构化输出能力，平台只需拥有候选矩阵、阈值、失败回退和持久化语义，不需要新增路由框架。
- 平台拥有：`operation=auto` 契约、附件归一化与候选矩阵、`0.85` 阈值、真实 operation 持久化、默认模型选择、幂等和恢复边界。
- 外部方案负责：AI SDK 负责结构化输出协议映射，LiteLLM 负责模型别名与上游访问，分类模型只在 Runtime 给定的候选集中返回意图和置信度。
- 明确不实现：前端关键词路由、分类模型直接执行图片操作、provider 原始分类文本存储和通用工作流引擎。

## 实施边界

Runtime 先根据已经规范化并校验所有权的附件形成候选集：

| 输入事实 | 允许的候选 operation | 处理 |
| --- | --- | --- |
| 无附件且无 `conversation_message` 引用 | `conversation.chat`、`image.generate` | 执行结构化分类；只有 `image.generate` 且 `confidence >= 0.85` 才生图 |
| 恰好一张受控、可读取且属于当前会话的 `image_asset`，无其他附件 | `conversation.chat`、`image.edit` | 执行结构化分类；只有 `image.edit` 且 `confidence >= 0.85` 才编辑 |
| 任意 `conversation_message` 引用、远程图片 URL、文档链接或多张图片 | 仅 `conversation.chat` | 直接对话或把分类结果钳制为对话，不允许图片副作用 |

分类 schema 只包含候选中的 `operation` 和范围为 `0..1` 的 `confidence`。分类返回 `conversation.chat`、图片候选置信度低于 `0.85`、超出候选、输出无法解析、非取消模型失败或剩余截止时间不足时，Runtime 均解析为 `conversation.chat`。分类发生在 Run 创建之前；直接调用方的取消信号会中止当前请求，不创建 Run，也不继续发起对话或图片模型调用。Demo 在尚未取得 `run-started` 时只记录停止意图，分类完成并取得 Run ID 后再按既有 Run 取消入口收口。分类阶段不创建图片资产，也不得把用户输入、附件内容或 provider 原始分类响应写入普通日志和 Trace。

Demo 普通输入区不展示 operation 或模型选择控件，新请求统一使用 `operation=auto` 且不提交 `model`。显式选择历史图片的“继续编辑”使用该资产和一次性的 `image.edit`；`retry`、`regenerate`、`continue` 从来源 Run 继承已经持久化的真实 operation。这些动作不执行分类，完成或取消恢复关系后 Composer 回到普通 auto 提交。Runtime 在业务模型调用前持久化或锁定真实 operation；完成态 requestId 重放直接返回原 Run。自动请求携带 `model` 时作为输入错误拒绝，实际业务调用始终读取解析 operation 对应的服务端 `defaultModels` 别名。

## 风险与退出路径

- 已知风险：分类增加首包延迟与调用成本；只在附件矩阵仍有两个候选时需要模型判断，单一对话候选可直接路由。高置信度仍可能误判；图片操作固定阈值、单次尝试和可观测计数，线上样本用于离线评测，不自动改阈值。
- 锁定点：结构化输出使用 AI SDK Core API，但分类 schema、候选矩阵和 Run operation 均为平台契约，不依赖 provider 原始响应格式。
- 退出路径：可把结构化分类 Adapter 替换为受评测的本地模型或确定性分类器；关闭自动分类时回退显式 operation，不迁移已有 Run，因为库内保存的始终是真实 operation。
- 维护责任：Agent Runtime 维护候选矩阵、阈值、分类 Prompt/schema、失败回退和回归样本；渠道只维护默认自动输入与显式历史操作入口。

## 验收与完成报告

- 验证证据：已覆盖附件矩阵、`0.8499/0.85` 阈值、非法结构、分类失败、auto 模型注入拒绝、真实 operation 持久化、requestId 重放、分类阶段请求中止/子截止时间，以及三个恢复动作继承 operation 且不调用分类器。
- 剩余边界：2026-08-15 当前配置已通过智能路由到两轮真实图片编辑，但智能路由正确不等于任意上游映射都可用，也不替代误路由率、质量、成本和异常矩阵验收。
- 文档与契约：同步 README、场景链、架构边界、stable OpenSpec 和 `add-smart-operation-routing` change。
- 重评条件：图片误路由率超过评测阈值、分类额外延迟/成本不可接受、operation 增长到需要分层路由，或产品要求所有图片副作用显式确认。
