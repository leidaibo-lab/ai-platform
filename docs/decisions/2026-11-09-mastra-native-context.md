## 问题、约束与非目标

累计资料读取、初始目录和 provider JSON 字节限制不能表达模型当前 token 上下文；将它们绑定到人工升档阻断正常工作。用户要求取消此门槛，显式采用 Mastra 原生上下文管理。保留固定版本引用、分页、单次工具返回边界、文件权限、人工审批及独立的模型调用次数治理。不新增自研压缩引擎，不迁移探索主线，不自动恢复真实 Run。

## 决策与实施边界

采用工厂组合原生 Memory。live 产品、开发v2、独立测试和部署角色启用 OM；Observer/Reflector 使用当前角色的同一显式模型配置及出口，不自动选择其他 provider。每次角色执行/重试使用唯一 thread/resource，执行中的工具历史可被观察压缩，不把上次失败片段、其他角色或其他 Run 带入本轮。审批事实仍归 Workflow，模型记忆不替代审批。

观察阈值为本地 token 估算的 24000，反思阈值为 12000；同步观察，禁用后台缓冲，失败中止当前调用并走原有检查点恢复，避免后台任务在节点结束后继续消耗模型。启用 provider 上下文溢出时的原生观察与一次重试。阈值触发内部压缩，不要求人工追加资料容量，也不声称适配所有模型窗口。fixture 正常业务流程不启用真实观察模型；另用脚本模型验证原生压缩。

资料装配只保留引用、散列、分页与单次读取大小，不限制累计读取、目录总量或模型请求体字节数。旧 contextBudgetLevel、故障和审批字段仅用于历史读取；旧预算失败按原有版本/权限检查恢复，无需追加档位，服务端拒绝新的升档参数。原始历史不改写。

## 风险、退出与完成边界

观察/反思会增加模型调用和有损摘要风险，原文仍可重新读取；提示要求保留来源、已确认约束和未决项。模型窗口必须结合实际模型验证，首次输入/系统提示过大仍可能被 provider 拒绝。框架恢复失败须明确失败而非发布部分正文。长材料真实模型质量、成本与生产多实例尚未验收，不用固定模型测试替代质量结论。维护者负责后续版本升级，模型窗口、摘要漏事实或延迟超出场景要求时重评；退出可停用 Memory，但不能恢复旧资料升档门槛。

## 开发上下文重复读取与结束原因排障

Run `5adf434b-5511-46a8-9ba7-9c7a8a728900` 的两次上下文失败分别耗时120173ms、135800ms，配置均为步骤600秒、总计1800秒。原生消息历史两次均以工具调用结束，含反复方法加载和两轮观察；第二次还把工程参考路径当作候选文件读取而得到工具错误。旧 Adapter 对所有非stop、非error返回直接抛出无细项的model-error，因此原记录没有finishReason，不能从耗时断言超时或回填旧诊断。

采用锁定 `@mastra/core@1.81.0` 的原生 `prepareStep` / `toolChoice:'none'` 为只读角色预留第12步输出。候选文件由readFile读取，去掉上下文输入里project/extra的重复正文，并明确交接参考路径和候选路径的工具归属。保留原有12步边界、Memory、方法实际读取校验、结构和引用校验、审批与写入权限；最后一步仍无法核实的内容必须公开为缺口，不代替成功证据。

未采用单纯增加maxSteps（放大重复读取与观察成本）或对model-error盲目自动重试（重复相同输入，仍可能耗尽步骤）。不新增自研压缩、消息裁剪或通用重试引擎。自研范围仅为角色提示、输入投影、原生回调装配和脱敏诊断，实践维护者负责；出现缺口被错误隐藏、频繁抵达最后一步或成本超出要求时重评读取组织方式。

新ModelFailure可选保存固定finishReason、steps、maxSteps与明确的结束分类，未知正文、SDK请求、URL和cause不持久化；旧可选字段不填默认值，避免历史恢复hash漂移。诊断Adapter与原生策略工厂分别负责事实归类和执行收束，保持单一职责；不改变探索主线稳定OpenSpec，也不新增依赖。
