# 需求入口双模式：逐项澄清与 AI 主动补全

## 状态

已采用（2026-11-15）。

## 问题

仅使用逐项澄清时，用户需要多轮主动回答，即使用户只想先得到一版推荐方案，也必须先完成大量业务选择。完全跳过需求澄清又会丢失人工确认边界。

## 决策

在 Mastra 产品入口增加版本化的 `intakeMode`：

- `clarify`：保留现有逐项澄清流程，推荐不升级为事实。
- `autofill`：产品经理 Agent 基于原始想法主动补全一条推荐闭环，生成包含假设、AI 建议和待确认项的产品稿，随后停在既有产品人工审批关口。

页面默认使用 `clarify`，用户通过“AI 主动补全需求”开关选择 `autofill`。服务端持久化入口策略；旧的 `guidedIntake` 输入继续兼容并映射到相应策略。

## 未采用

- 不删除逐项澄清：高风险或规则复杂的需求仍需要用户逐项确认。
- 不让 `autofill` 自动批准产品稿或自动进入研发：主动补全只减少信息采集轮次，不改变既有人工质量门。
- 不新增第三套状态机：复用现有产品团队、产品质量检查和人工审批流程。

## 影响与边界

`autofill` 的模型推断只能作为推荐和待确认内容，产品稿必须保留可审阅标记。真实模型质量、业务判断准确性和研发开工条件仍由后续人工门禁负责。

## 验证

- `tests/guided-intake.test.ts` 覆盖 Workflow 与 HTTP 入口选择 `autofill` 后直接停在 `review-product`。
- `npm run check`、定向测试、前端构建和 OpenSpec 严格校验作为交付验证。
