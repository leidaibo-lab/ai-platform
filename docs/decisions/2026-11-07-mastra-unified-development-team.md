## 问题与约束

Studio 仅注册产品批准即结束的流程，开发执行留在 CLI，用户看不到完整产研链。用户明确要求一条完整流程并替换旧入口，包含前后端并行、动态团队和委派。沿用 Mastra 1.81.0 原生 Workflow、Agent、LibSQL、固定检查及批准契约，不扩大项目 manifest 权限。产品批准后确认 manifest；源码、团队/任务及方法绑定技术方案批准。测试阶段和生产部署不在本轮。

## 候选与证据

| 路线 | 证据与选择 |
| --- | --- |
| Mastra Agent network 整体路由 | 锁定包 `agent/subagent.d.ts` 支持子 Agent，但自由路由不能代替当前任务依赖、文件归属、人工批准和交付证据，暂不作为主编排 |
| 原生 Workflow 嵌套与 parallel/foreach，加任务作用域工具 | 锁定包 `workflows/workflow.d.ts` 支持 Workflow 作为 Step、parallel、foreach concurrency；采用，以原生持久化和图展示为主 |
| 自建通用团队调度引擎 | 会重复 Workflow、暂停和存储，不采用；仅保留依赖波次、受限委派和补丁合并的业务适配 |

官方文档检索地址为 https://mastra.ai/docs/workflows/control-flow 与 https://mastra.ai/docs/agents/networks；当前实施依据以实际锁定包类型和源码为准，不假定线上文档对应同一版本。

## 决策和数据

选择**适配**原生 Workflow/Agent。Studio 只公开 `productDevelopmentWorkflow`，从四产品角色、产品审批、项目范围确认到开发准备/方案审批/团队执行/自检/评审/交付。旧源文件和历史数据库保留，不再注册旧 Studio 入口。

团队成员由架构任务生成，包括成员 ID、实现角色、任务和文件范围。实现角色可在自身任务内通过 delegateTask 工具创建具名子 Agent；不得扩大路径、角色、工具、递归深度和调用预算。委派不是无限权限，跨责任修改须重规划和重新批准。

同一依赖波次的任务通过原生 foreach 并发执行，最多3个。每任务复制同一基线到独立候选目录，仅读写自己的批准文件；宿主在所有分支结束后检查基线、路径、结果和预算，串行合并成功补丁。故障分支不回滚其他分支。持久化成功任务、失败位置、团队和委派证据。整体检查和独立评审仍是交付前置条件。跨实例与强杀进程中途的任意恢复不承诺。

## 实施与兼容

涉及完整 Workflow、v2 开发步骤装配、团队契约/执行适配、共享应用入口和文档。运行目录由原生 Run ID 散列派生，客户端不能传宿主路径；每步装配/关闭执行 Adapter，避免不同 Run 共用可变实例。旧 CLI 入口仅保留为历史兼容实现，不在 Studio 列表展示。选择回退时重新注册旧工厂，保留新 Run 证据，不能将新交付降级。
