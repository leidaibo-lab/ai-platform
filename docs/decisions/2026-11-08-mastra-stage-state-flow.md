# 按实际阶段执行开发流程并就地提示可恢复故障

- 状态：接受
- 日期：2026-11-08
- 负责人：Mastra 实践维护者
- 范围：独立实践，细化既有原生 Workflow 决策；不改变探索主线 OpenSpec 契约。

## 问题与约束

线性开发流水线在角色故障后仍经过所有步骤，每个空操作正常返回，Studio 将未做业务的节点标成 Completed。前端只显示内部 phase/kind，无法解释用户应做什么。用户要求友好阶段提示和严格状态流转。保持现有审批、检查点、调用预算、原生 Store 和历史恢复入口；不自动批准或重跑真实用户 Run。

## 候选与选择

| 路线 | 证据与判断 |
| --- | --- |
| 所有异常直接抛出、仅用原生 Time travel | 引擎真实 failed，但会丢失当前业务恢复状态/预算，不能等价保留既有人工暂停契约；不采用 |
| 原生 branch/dountil 和故障阶段 suspend/resume | 锁定 @mastra/core 1.81.0 的 workflow/step 类型提供条件分支、suspendData、恢复；采用，避免未执行节点假完成 |
| UI 根据 phase 隐藏绿色节点或自建状态引擎 | Studio 与事实仍不一致，且重复原生执行/存储；不采用 |

选择**适配**原生控制流。每个业务节点使用原生条件分支，只有命中当前阶段才执行，正常返回才推进；模型可恢复故障在原阶段暂停，保存分类、失败尝试和源码检查点，由人重试/停止。暂停是引擎 suspended，业务展示“该阶段执行未完成，等待重试”，不能伪造引擎 failed。不可恢复错误与恢复预算耗尽应抛出异常，真正 failed。保留 recover-development 兼容历史已暂停记录；不篡改历史 Completed 事实。

## 数据与实施边界

影响 development-v2、intake 关口投影、前端恢复表单与测试。故障阶段 suspendPayload 内保存 recoveryState 供恢复预算和源码校验，服务端仅投影安全摘要，不能把完整源码暴露为确认材料。继续使用既有 hash、reviewer、comment、retry/stop 输入；实际阶段的暂停路径由服务端决定。UI 展示阶段、问题、已保留内容、下一步及明确按钮，不预选处理决定，不要求用户解释系统超时。历史恢复入口保持同一契约。

采用条件分支与薄步骤装饰器，业务状态仍是 StateV2；无新依赖、通用调度器或第二事实源。停在源码检查点，成功任务不重放，未批准不能进入实施，开发未交付不继续测试/发布。维护者负责版本兼容与原生图验证。若原生嵌套恢复不兼容，应保留旧流程恢复路径而不是修改用户快照或重建需求。

## 验收与退出

- 验证模型超时后原阶段 suspended、后续业务节点未执行，阶段解释与原生状态一致。
- 验证同 Store 重开恢复、旧 recover-development 恢复、旧 hash 拒绝、停止不推进、重复故障和预算耗尽关闭。
- 正常批准、动态团队、独立检查和评审全量回归；UI 验证明确指引与取消确认无副作用。
- 真实模型质量不以 fixture 代替；本轮不自动重试真实用户 Run。

控制流变更或 Mastra 升级时重评；需要放弃时回退工厂实现，保留所有持久化运行事实与未决批准。

## 实施细节

正式装配使用 `branch` 包裹阶段和 `state-after-*` 映射传递状态，未命中阶段不执行。映射节点是控制流节点，其完成不代表业务阶段完成。可恢复角色和团队节点由薄装饰器在原阶段 `suspend`；使用原生 `suspendData` 恢复失败后的状态，核对源码和身份后才重试。团队已成功分支的补丁与任务完成集保留。`legacySequential` 工厂选项只用于历史图迁移回归，正式入口不启用。

`initialize-delivery-lifecycle` 在开发未交付时原生 `bail`，不再让测试、发布和最终交付节点空跑并显示成功。用户明确停止会正常保存阻塞终态（引擎 success 不等于业务交付成功），前端根据业务 outcome 显示停止；故障重试耗尽使用真实 failed。

页面验证已在现有用户暂停记录上完成：阶段/原因/保留内容/操作指引和二次确认显示正常，取消不提交决定。未重试或停止真实需求，未改写历史快照。原生迁移回归验证旧恢复节点跨Store重新装配后仍能进入方案批准。

## 同日超时诊断补充

架构角色改为步骤300秒/Agent总计600秒，其余角色90秒/180秒。白名单诊断保存来源、实际触发时限（明确存在时）、HTTP状态或传输代码、实际耗时、记录时间、调用序号及所用策略版本。最终失败用应用自己的安全Error.details保留最近八次尝试，原生Store序列化拥有事实；不附带SDK原cause或源码，旧可选字段不填默认值，不修改历史hash。

重试次数与总调用限制保持，实际生效范围为后续模型调用；不自动恢复用户失败Run，不把延长本地时限当作上游服务限制也已延长。诊断来源缺失明确标未知，不能用约202秒总耗时反推某个时限。独立单元与原生跨Store回归覆盖来源分类、脱敏和最终尝试持久化；真实模型质量需另验。
