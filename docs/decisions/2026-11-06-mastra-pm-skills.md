- 日期：2026-11-06
- 负责人：Mastra 实践维护者
- 所属区域：`practices/mastra` 独立原生应用实践
- 关联需求：将 phuryn/pm-skills 全套能力放入 Mastra 的 `.agents/skills/`，供产品 Agent 使用。
- 关联 OpenSpec：不涉及探索主线稳定契约；未改变根 Runtime、API、配置或密钥边界。
- 替代记录：无；细化原生实践分工，与固定产品角色决策互补，不在本次实现额外角色。

## 问题

现有产品 Agent 只有需求交接 Skill，无法按任务选择上游的发现、战略、市场、分析、增长与交付方法。仅复制插件或首页会遗漏流程命令、引用资源及已迁移的 shipping 实现。成功标准是完整库存可审计、中文入口可发现、参考资料可通过原生工具读取，并保留人工交付关口。

## 约束与非目标

用户指定 `practices/mastra/.agents/skills/` 为单一落点；这是根 Skill 目录规则的显式实践作用域例外。沿用两级路径、职能前缀、中文正文、模式/作者/版本元数据和治理校验。固定上游版本并保留 MIT 原文与逐文件散列，启动不联网。

复用 `@mastra/core 1.81.0` 原生 `createSkill`、`skill`、`skill_read`、`skill_search`，不引入 Workspace、执行引擎、模型依赖升级或动态委派。Skill 是方法，不授予网络、仓库、SQL、命令、部署或审批权限；需要缺失工具的步骤应报告输入/能力缺口。真实模型能力、产品质量提升、全量业务评测与生产发布不在本次验收范围。

## 候选方案

| 候选 | 路线 | 依据与优势 | 缺口/取舍 |
| --- | --- | --- | --- |
| 直接安装上游 Claude 插件 | 成熟一体化 | 上游提供 marketplace、69 个 skills 与42个 commands | 插件宿主、命令和命名约定不符合当前 Mastra 及公司目录；shipping 8项仅为迁移提示 |
| 中文入口 + 原文资源 + Mastra 原生 Skill | 轻量可组合适配 | 本地锁定包支持 inline metadata/license/references；现有 Agent 已用 createSkill | 需要维护译写入口、引用映射、来源清单及加载 Adapter |
| 自写产品提示与工具路由器 | 最小自研 | 可按当前业务精简 | 不满足用户整套迁移目标，重复建设上游方法和框架加载能力 |

## 淘汰条件

遗漏任一上游入口、仅复制迁移提示、丢失许可、运行时下载、不适配命名而产生断链、以文本代替实际执行证据、绕过人工批准，均不接受。

原生 API 依据为锁定安装包的 `docs-skills.md`、`reference-agents-createSkill.md`、`skills/types.d.ts` 和 `workspace/skills/tools.d.ts`。后续验证库存、散列、跨技能依赖、原生多步读取、交付与修订暂停恢复；结果见文末。

## 决策

- 结论：适配。
- 选择：111 个入口分别落为 `product-pm/<原名>/SKILL.md`，原 commands 使用 `flow-` 前缀；另增1个本地目录导航 Skill。
- 平台拥有：中文执行入口、公司治理、来源锁、Mastra 加载 Adapter、角色指令与有限调用预算。
- 外部方案负责：产品方法原文及 Mastra 原生发现、读取与工具循环。
- 保留根需求交接 Skill；产品工作按任务选择方法，交付/修订产品稿仍需需求交接检查；开发、测试、运维和阅读助手维持角色范围。

## 未采用方案及原因

直接插件安装不能在当前宿主自动使用 commands，且不符合公司规范。最小自写提示丢失整套覆盖。只有用户缩小范围、公司规范改变或框架加载能力发生不兼容时重评。

## 实施边界与计划

- 资产：`practices/mastra/.agents/skills/`，111项源入口、中文正文、精确保留的原文、附属参考、许可证、来源锁与索引。索引/导航明确原始名称到本地名称的关系。
- Adapter：`src/mastra/agents/skills.ts` 从显式根读取两级目录；交给 createSkill 的 metadata/license/references 完整保留。配置或资源错误使启动失败，不静默跳过。
- 数据结构：来源锁是版本1的只读 JSON，包含仓库/SHA、每项类型/原路径/本地名称/依赖、源文件和附属文件散列；Agent 不写来源锁。Skill 对象由应用启动时拥有，不存业务数据。
- 模式：Adapter 只适配资产布局和框架输入；流程由 Mastra 持有。中文方法正文和原始资料渐进加载，避免把111份全文常驻系统提示。
- 产品默认、交付和修订使用同一有限步骤预算（每次生成24步）；多技能工作可连续调用，不开放无限循环。
- 根治理只增加一个显式实践根并同步索引/规则，不递归收集任意外部 checkout。
- 依赖与配置：沿用现有锁定版本，无新密钥、无数据库迁移。已有快照/人工版本审批不变。
- 顺序：接受适配范围→生成资产和索引→原生装配→确定性工具/资源验证→现有回归→记录实际结果。

## 风险与退出路径

111个描述增加发现上下文成本；短描述和按需读取避免111份全文常驻。上游英文原文保真归档，中文入口承担宿主与工具边界适配，不承诺逐字翻译；原文中的插件命令、工具授权、写路径或指定模型不自动生效。维护者升级时对比源清单、迁移指向、许可和方法变化，再更新本地译写与回归，禁止自动拉取 HEAD。

回退可移除产品整套注册，保留原需求交接 Skill；Markdown 资产和来源锁仍可导出。没有业务事实存储迁移。若描述规模、真实路由质量或步数/成本不能满足业务，再评估原生搜索处理器或按职能缩小挂载。
