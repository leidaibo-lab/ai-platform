# 为 Mastra 产品角色持久化细粒度诊断事实

- 状态：接受
- 日期：2026-11-13
- 负责人：Mastra 实践维护者
- 所属区域：Agent Runtime / 治理与可观测
- 关联需求：产品诊断轨迹不能只展示运行状态，后端需要承接阶段、模型、工具和输出事实
- 关联 OpenSpec：`openspec/changes/add-durable-product-diagnostics/`
- 替代记录：扩展 `2026-11-10-mastra-execution-control.md` 的诊断边界；不改变其进程内取消职责

## 问题

当前产品角色只保存正文、工具名称、模型步骤数和有限生成结束证据。诊断投影因此只能展示“进行中、完成几步、最近活动时间”，无法回答阶段目标、输入引用、模型调用统计、工具结果事实、输出结构和下一步是什么。

成功证据是：每个新产品角色产物都能从持久化 Workflow 快照中回读版本化诊断对象，并且诊断摘要不依赖进程内 `Map`；已有产品角色回归仍能通过，正文和审批事实不被改变。

## 约束与非目标

### 必须满足

- Mastra Workflow 继续作为本实践的运行事实源，不引入第二套调度器。
- 原始 prompt、工具正文、凭据和模型私有逐字思维链不得进入公开诊断数据。
- 新记录必须包含阶段目标、输入引用、模型调用、工具事实、输出摘要、失败尝试和下一步。
- 当前处于开发/测试阶段，不为旧历史 Run 保留兼容回退；旧历史 Run 可以删除。

### 本次不解决

- 不实现独立诊断事件数据库、跨实例实时事件流或历史 Run 迁移。
- 不要求模型在本次切片返回完整 findings/decisions 结构化业务分析；字段扩展在后续独立契约中完成。
- 不把诊断记录解释为质量通过、人工批准或模型私有推理。

## 候选方案

| 候选 | 路线 | 覆盖范围 | 关键优势 | 关键缺口或风险 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 直接扩展 Mastra Workflow 快照 | 轻量可组合 | 产品角色阶段事实 | 复用现有持久化、恢复和读取入口，变更小 | 事件量增长后快照可能变大 | `src/mastra/workflows/product-contract.ts`、`product.ts` |
| 独立 LibSQL 诊断事件表 | 轻量可组合 | 不可变事件、游标和跨页面读取 | 适合细粒度事件和增量读取 | 需要新的 Store Port、事务边界和迁移 | 当前 Mastra LibSQL Store 与已有 Workflow 快照边界 |
| 采用外部可观测平台作为业务事实源 | 成熟一体化 | Trace、检索和运营观察 | 查询能力成熟 | 不能拥有业务审批/产物事实，增加部署和脱敏边界 | 当前 ChainTrace 决策与实践运行事实边界 |

## 淘汰条件

- 不能保证新 Run 的诊断字段与产品产物同一快照提交的方案不得采用。
- 需要保存原始模型隐藏推理、未脱敏工具正文或凭据的方案不得采用。
- 把 Trace 后端当作产品审批或恢复事实源的方案不得采用。

## 决策

- 结论：适配
- 选择方案：第一阶段适配 Mastra Workflow 快照，在 `productWork.entries[].diagnostic` 下保存版本化 `product-diagnostic.v1`。
- 决策依据：当前规模和开发/测试阶段优先复用已有事实所有权，避免先引入独立事件表导致第二套持久化和迁移边界。
- 平台拥有：诊断 Schema、阶段目标、输入/输出 Hash、工具事实投影、脱敏规则和业务投影。
- 外部方案负责：Mastra Workflow 的快照持久化、恢复和状态生命周期。
- 明确不实现：旧历史 Run 兼容、独立诊断事件表、模型私有推理保存。

## 未采用方案及原因

## 实施边界

- `execution-control.ts` 继续负责进程内取消和活动观察，不承担历史诊断。
- `product-generation.ts` 提供模型生成结束证据和失败尝试。
- `product.ts` 负责将角色输入、模型结果和工具步骤投影为 `product-diagnostic.v1`。
- `service.ts` 只读取诊断事实并生成展示投影，不补造旧字段事实。
- 开发/测试阶段新契约直接升级；旧历史 Run 可删除，不增加 fallback 或双写迁移。

## 实施计划

- 受影响路径：`src/mastra/workflows/product-contract.ts`、`src/mastra/workflows/product.ts`、`src/intake/service.ts`、`web/src/DiagnosticTrace.tsx`、产品回归测试。
- 核心数据结构：版本化 `product-diagnostic.v1`；Hash 和引用只读，工具事实脱敏，正文仍由 `content` 字段拥有。
- 遵循的模式：现有 Workflow 快照 + Adapter 投影；运行观察和持久化产物保持单一职责。
- 不采用的模式：不把前端展示文案写回 Workflow，不把进程内观察 Map 作为历史事实。
- 依赖与配置：不新增依赖和配置。
- 实施顺序：Schema → 角色产物投影 → 服务端诊断摘要 → 前端工具事实展示 → 回归。
- 兼容与迁移：当前开发/测试阶段不迁移旧历史 Run；旧数据允许删除。
