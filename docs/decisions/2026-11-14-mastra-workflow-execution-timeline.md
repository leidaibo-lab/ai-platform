# Mastra Workflow 执行时间线采用原生 watch 与快照投影

- 状态：接受
- 日期：2026-11-14
- 负责人：AI 应用基础平台维护者
- 所属区域：渠道与体验层 / Agent Runtime
- 关联需求：在 Mastra 产研工作台展示类似 Codex 的当前节点、耗时、工具和文件读取事实
- 关联 OpenSpec：不涉及探索稳定契约；仅扩展 Mastra 主线的工作台投影（迁移前路径：`practices/mastra`）
- 替代记录：无

## 问题

当前 Mastra 工作台能够读取 Workflow 快照并展示六个业务阶段，但执行中主要依赖 5 秒轮询，页面不能即时显示节点切换、节点耗时、工具调用和已读取文件。目标是在不改变 Mastra Workflow、Store、暂停恢复和审批事实所有权的前提下，提供可复核的执行时间线。

## 约束与非目标

### 必须满足

- Mastra Workflow 和 Mastra Store 继续拥有执行状态、暂停点和恢复事实。
- 实时 UI 只消费 `Workflow.watch()` 的事件；历史和刷新通过 Workflow 快照重建。
- 文件、工具和模型信息只公开经过白名单投影的元数据，不展示密钥、完整工具结果或任意文件内容。
- 页面只能展示安全执行摘要，不展示模型隐藏思维链。

### 本次不解决

- 不自建 Broker、任务队列或第二套持久化执行状态。
- 不把原始模型 reasoning token 转发到浏览器。
- 不承诺跨进程、多实例实时事件投递；当前实践仍是本机单实例。

## 候选方案

| 候选 | 路线 | 结论 |
| --- | --- | --- |
| Mastra `Workflow.watch()` + `WorkflowState` 快照 | 成熟一体化/原生适配 | 已采用；事件负责实时唤醒，快照负责权威状态和历史重建 |
| 自建 EventEmitter、事件表或 Broker | 最小自研/基础设施 | 不采用；会制造第二事实源，超出本机实践范围 |
| 仅前端计时与 5 秒轮询 | 最小 UI 改造 | 不采用；无法准确表达服务端节点边界和真实工具/文件事实 |

## 决策

- 结论：适配
- 选择方案：Mastra 原生 `Workflow.watch()` 事件 + `WorkflowState` 的 `startedAt/endedAt` 快照投影
- 决策依据：Mastra 已提供 Workflow/Step 生命周期事件和持久化步骤时间字段，能够覆盖实时观察、刷新恢复和历史查看，不需要复制调度与存储能力。
- 项目拥有：安全 `RunTimeline` 投影、公开字段白名单、工作台 SSE Adapter 和 UI 展示语义。
- Mastra 负责：Workflow 执行、事件发布、步骤状态、暂停恢复和 Store 持久化。
- 明确不实现：原始 CoT、跨实例事件总线、独立执行审计库和浏览器事实源。

## 实施边界

- 服务端通过 `Workflow.watch()` 过滤目标 `runId`，映射为工作台专用 SSE 事件。
- `readIntake()` 从原生快照重建节点时间线；Step 的开始/结束时间直接使用 Mastra 已保存字段。
- 工具名称来自已保存 `work` 结果，文件路径来自已读取上下文文件清单；均只返回元数据。
- 前端通过 SSE 触发快照刷新，保留 REST 回读作为断线兜底；不把 SSE 本身当作恢复事实。

## 风险与退出路径

- 已知风险：`Workflow.watch()` 是当前 Mastra 实例内的观察入口，多实例场景不能保证事件送达；通过快照轮询和刷新回读兜底。
- 退出路径：未来需要跨实例实时交付时，保留 `RunTimeline` 投影和 SSE Adapter，替换事件来源为有界的成熟消息/交付方案。
- 维护责任：Mastra 实践维护者负责事件字段白名单、快照投影和工作台回归。
