# 受控恢复旧版开发初始化失败

- 状态：接受（用户批准先前提出的分阶段方案）
- 日期：2026-11-18
- 负责人：Mastra 主线维护者
- 关联：[阶段状态](./2026-11-08-mastra-stage-state-flow.md)、[Harness 职责](./2026-11-18-platform-team-harness.md)、[恢复契约](../../openspec/changes/promote-mastra-v2/specs/development-initialization-recovery/spec.md)

## 问题与范围

产品已批准并确认项目后，旧逐行锚点上限会使开发初始化失败，工作台没有恢复入口。需要保留同一 Run 的批准与候选，只重试未实施的规划。不得重放项目批准、绕过工程准备或新增第二运行事实源。

## 选项与决定

采用**适配**现有 Mastra Store 与受控 Time travel：仅识别旧锚点上限的固定错误，并验证同 Run 产品批准、项目输入、下游未开始及原候选内容。重试固定开发执行入口，后续仍须技术方案审批。未知错误和有副作用阶段不因本决策获得重放权限。

任意节点重试无法保证副作用与审批安全，不采用；自建恢复数据库和执行引擎会形成第二事实源，不采用。无需新增依赖或更改 Workflow ID。原生嵌套图与同进程并发保护须通过回归；跨进程原子恢复、外部写入结果核对及通用节点策略仍是后续工作。

## 实施与验收

变更范围为 `src/intake/recovery.ts`、`src/intake/service.ts`、研发执行解析器和相关测试。恢复令牌绑定失败快照；服务端重新校验候选，候选缺失或漂移即拒绝，不能重新播种。恢复可能调用模型并产生费用，检查和审批约束保持。运行状态与失败记录仍由 Mastra Store 保存。

- [ ] 合成真实 Workflow 从失败恢复后停在方案批准，且不实施。
- [ ] 旧令牌、审批篡改、下游已执行和候选漂移均拒绝。
- [ ] 跨 Store 重新装配及重复请求验证。
- [ ] 类型、相关回归、OpenSpec 与 diff 检查。
- [ ] 真实 Run 验证单独报告；不将 fixture 测试视为真实模型质量。

维护者在多进程部署、Mastra 恢复语义变化或新增外部副作用时重新评估。退出时关闭此错误的恢复白名单并保留原生运行事实。
