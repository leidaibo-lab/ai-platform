# 受控恢复未实施的开发阶段

- 日期：2026-11-18
- 状态：接受
- 决定类型：运行治理与恢复
- 关联：[开发初始化恢复](./2026-11-18-recover-development-initialization.md)、[Harness 职责](./2026-11-18-platform-team-harness.md)、[阶段恢复契约](../../openspec/changes/promote-mastra-v2/specs/development-stage-recovery/spec.md)

## 背景

HRM Run 在技术方案生成暂停后重试时，远端同步缓存装饰器将旧的 `suspend` 记录按已生成架构结果回放。该记录是原生人工恢复暂停包，不符合架构方案状态结构，导致 Run 以结构校验错误失败。

## 决定

缓存装饰器只把 `result` 作为已生成角色结果复用；`suspend` 仅在资料同步重试时重放。若架构节点接收到原生恢复决定，则必须回到该节点消费决定并重新调用该阶段。

对已经由该兼容问题失败的 Run，只在以下条件都成立时提供恢复：同一 Run 的产品批准存在、开发状态仍处于架构阶段、上下文与执行身份未漂移、候选源码散列一致、没有实现/测试/发布/交付副作用。恢复只重新进入架构生成；方案仍需人工批准。

## 后果

- 避免把控制流暂停包误当业务方案，保留同步重试对已生成结果的复用。
- 失败阶段始终保留在 Mastra Store；文件缓存不是审批或恢复事实源。
- 缓存状态未知、存在副作用或版本不一致时关闭恢复，交由人工调查。
