## 问题与目标

产品角色的提示词和 Skill 在进程装配时来自代码和本地文件，缺少跨团队发布和版本选择。目标是在新 Run 中使用经审核发布的 Nacos Prompt 和 Skill，并能在暂停恢复后核对并继续使用原资源。Mastra Store 继续拥有执行和审批事实。

## 候选与倾向

| 候选 | 类型 | 收益 | 缺口与取舍 |
| --- | --- | --- | --- |
| Nacos 3.3 AI Registry + Mastra 原生 Skill | 成熟组合 | 复用资源生命周期、发现和原生 Skill 装配 | TypeScript 端接口、资源持久化和鉴权需验证 |
| Git 版本资源 + Mastra 原生 Skill | 轻量组合 | 可审查和回滚，无新增注册中心 | 缺少统一动态发现与运营发布；可作为禁用 Nacos 的历史兼容路径 |
| 自建注册、版本和工具协议 | 最小自研 | 可定制 | 重复实现生命周期和协议，维护负担大，不采用 |

结论为**适配** Nacos 3.3 Client API、Mastra 原生 Skill 与受控 ZIP 解包；平台负责 Run 资源快照、权限交集、结果证据与失效处理；Nacos 负责资源管理和发现，Mastra 负责运行与恢复。MCP、A2A 和远程 Agent 不在本次范围。

目前代码是验证切片，尚不能据此将决策标记为接受或将所有产品资源视为已迁移。角色绑定、完整资源发布、真实模型质量和目标环境的权限与恢复仍需证据。

## 关键约束和验证

- 仅加载发布且可见的明确版本；Prompt 和 Skill 内容绑定 SHA-256 和来源身份。仅有 hash 而无法恢复内容不能满足冻结要求。
- 冻结内容由 Mastra Store 持有或引用经验证的不可变归档；运行中变更只影响新 Run。旧 Run 走原逻辑，不能伪造冻结事实。
- 可撤销授权优先于缓存；撤销时阻止后续调用，不改写历史事实。不可用时以安全失败或人工处理为准。
- 禁止从远程 Skill 获得额外执行权限；资源发现不等于授权。
- 校验超时、响应大小、凭据脱敏及内容完整性。未经验证不能声称可用于生产。
- Prompt 固定不可覆盖的宿主安全边界，模板变量由宿主校验；区分固定模型控制流测试与真实模型质量评测。

## 实施与验收计划

1. 核对 Nacos Client API、Skill 包格式和生命周期状态；用本地隔离 Nacos 验证。
2. 在新版本 Workflow 初始化步骤冻结资源及其内容，恢复时读取原快照；验证重启、版本变化、缺失、篡改与回退。
3. 接入 Prompt 与 Skill，默认启用 Nacos 并为旧 Run 保留兼容路径。
4. 验证权限拒绝、网络故障、撤销、恶意资源、凭据泄漏、工具调用与审批事实；分别记录 fixture 和真实模型结果。

运行态数据结构、适配实现、依赖版本和部署配置待上述验证确定。验证通过后再接受决策并进入正式实现；不得把此提议当作已交付能力。退出时新 Run 可切回本地资源，已启动 Run 继续使用已冻结版本或明确停止。

参考：[Nacos Client API](https://nacos.io/en/docs/latest/manual/user/open-api/)、[Nacos 3.3 发布说明](https://nacos.io/blog/release-330/)、[Mastra MCP](https://mastra.ai/docs/connections/mcp)。

## 2026-11-17 范围调整与补充验证

## 2026-11-17 本机真实资源与 live 流程验证

在本机独立 Nacos 3.3.0 容器中发布两个候选角色 Prompt 和 113 项产品 Skill，逐项下载比对；Nacos 会规范化 Skill 的 YAML frontmatter，导入器以 Mastra 解析后的元数据、正文及完整参考资料比较，冻结摘要仍基于实际下载内容。专用普通账号可以读取两项 Prompt 和全部 Skill，尝试创建合成 Prompt 返回 403。测试容器使用本地持久化卷，权限仅为本机环境证据。

带 Nacos 的真实模型合成 Run `365b4224-576b-43bd-bb9f-3254a1ef4aa5` 在初始化快照冻结两项 Prompt、113 项 Skill 和审查角色 3 项绑定；产品分析、范围和写作中观察到 `skill` 和 `skill_read` 工具事实，产品稿和审查完成后进入研发规划。研发 `assess-readiness` 因 `invalid-output` 暂停；按保存检查点重试时提示“恢复版本发生漂移”，Run 失败，后续实现、测试和部署未完成。未启用 Nacos 的对照 Run 同样在就绪审查因无效模型输出暂停；这支持把该失败作为研发路径的独立问题跟进，但尚不能断言根因。既有阶段和阻塞回流 Prompt 仍有代码内文本，不能声称产品提示词已全部由 Nacos 接管。真实模型质量、恢复问题及完整产研链路仍待验收。

同日后续复现确认：无效输出的故障对象构造时 `modelCall` 位于 `diagnostic` 之前，持久化 schema 将两者调换，而恢复摘要使用 JSON 属性顺序。现按 schema 顺序生成新故障；历史摘要仅在原始完整状态可按旧顺序精确匹配时兼容，篡改和检查点校验仍有效。确定性测试覆盖暂停、存储重开、重试、旧顺序与篡改；历史真实快照的旧摘要匹配通过，不能宣称已成功重试此前失败的 Run。

修复后重新启动带 Nacos 的真实模型 Run `e7daa3cb-2566-44dd-a38e-c4b326e2e6a3`：产品与审查完成、合成评测确认产品与项目范围；研发规划将产品稿中生成时的“待审批”文字误判为业务阻塞，尽管 Workflow 已保存同版本批准。回流产品澄清时，模型两次输出不符合阻塞来源与问题分类的 schema，Run 失败；已使用既有只读生成恢复入口重试一次，仍失败。该次未到恢复摘要校验节点，也未完成研发、测试或部署。此阻塞不证明 Nacos 不可用；审批事实向研发和澄清模型传递、结构输出质量需要后续单独修复与验证。

后续修复在相同 Run 中投影同版本产品批准，明确区分已批准产品与待审批技术方案；阻塞 Schema 向模型表达必答和可选的分类，并要求有阻塞时输出问题。原 Run 成功恢复澄清、经评测者确认两次修订稿并重新规划。就绪审查多次遗漏覆盖锚点后，增加固定脱敏诊断及可见的引用范围和覆盖数量约束；此后模型返回了覆盖 273 条原文和任务的结构化报告。真实重试也成功通过原恢复摘要校验。
