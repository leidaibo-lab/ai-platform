## 问题与约束

已有交接只生成提案，无法证明开发 Agent 能读写代码、处理失败并提交真实自检证据。用户要求只建设开发阶段，在交付包处结束。保留现有产品四阶段交接和历史暂停快照，另注册开发执行 Workflow，不隐式启动测试或部署。

使用当前锁定 @mastra/core 1.81.0、@mastra/libsql 1.28.0、Node.js 24；不新增调度引擎、不升级依赖、不共享探索数据或凭据。代码只在新建案例目录运行，工具不接受任意命令。架构确认绑定当前 hash；模型不能批准自己的方案。能力评测允许独立标记的组织者规则确认，但不伪造人工审批。

## 淘汰条件与关键验证

禁止无隔离 fallback；不能使用带真实密钥的环境执行候选代码；Agent 无权修改公开检查/隐藏答案；失败或缺失证据不能放行。验证路径穿越、符号链接、越界读取/写入和网络阻断，再运行真实 node 检查。Docker 当前不可用不作为绕过隔离的理由。

## 决策与实施边界

结论为**适配**：Mastra 原生 Workflow + Agent + LocalFilesystem + LocalSandbox；实践只拥有角色权限、manifest、批准/交付 hash、固定检查白名单与外部评测资产。macOS 自定义 Seatbelt 只开放运行系统、指定 Node 目录、案例目录和独占临时目录；不采用默认允许读全盘策略。Linux 未经实测不承诺可用。没有可用隔离后端则失败，保留证据。

开发角色固定为架构、前端、后端、按需基础设施、自检；协调器以原生循环执行有界返工。自检角色只读，检查证据来自执行 Adapter；前后端仅可写批准任务文件，检查文件不可修改。任务首版串行，后续只有契约冻结且范围不冲突时才可并行。

初版执行覆盖不联网、不安装依赖的 Node ESM 切片，已有项目脚本需单独审查后扩展固定命令清单。24 个能力案例是12类离线切片，不能推断 Next/Nest/PostgreSQL/Prisma 整栈、真实浏览器、数据库迁移、分布式队列或生产能力通过。截图技术栈仍为候选；整栈环境可用并完成选型后追加真实项目验收。

## 实施计划

新增 `src/mastra/workflows/development.ts`、开发角色工厂、`src/development-service.ts`、执行 Adapter、专用 CLI、评测 Runner 与24案例。注册独立 Workflow，旧 delivery 不迁移。输入 manifest 有已确认产品来源、初始文件、允许写入路径及公开检查；方案/记录/交付返回新对象，原生 Store 是运行事实源。采用工厂、Adapter 和固定责任路由；I/O 与协议校验分离，避免泛化执行平台。

## 风险、退出与维护

### 2026-11-06 补充：澄清和故障接续

采用原生 Workflow 新 Run 与 suspend/resume，不使用 restart 重放失败实现，也不直接修改 Store 快照。澄清是需求版本边界：保留原 `clarification-required` Run；产品负责人提供新的已批准产品 Run 后，以当前候选快照创建带来源链的新开发 Run，技术方案必须重新批准。评测组织者修订合成规则单独标记，不能冒充产品批准。

模型超时、DNS/网络或临时服务故障在单角色调用内最多自动重试一次。候选只有显式文件写入，无外部副作用；失败时先恢复调用前文件快照并验证 hash，再允许重试。记录每次失败类别、角色、轮次、部分源码 hash、回滚检查点和未知用量；不保存 SDK 原始错误或请求。不可恢复的漂移直接失败，不能继续放行。自动重试耗尽或结构输出无效时，原生流程暂停于恢复关口；人工确认当前输入/方案/检查点 hash 后最多再接续一次。已完成角色不重复执行，接续后仍重新运行固定自检。检查失败走原有有界返工，不视为网络故障。

此恢复只覆盖被进程捕获并成功回滚的模型调用失败；进程被强杀、磁盘损坏、远程副作用和跨实例自动接管不在承诺范围。错误日志使用原生静默 logger，输出固定分类；不全局替换 console 或捕获后打印请求体。采用原生暂停而非自动重启的原因是避免不清楚的副作用重放；人工一次接续用尽后终止并保留证据，不以重跑挑成功。

Seatbelt 是本地进程约束，不等于容器/VM资源隔离；初版固定30秒检查、有限工具步数和输出长度，不适合不可信多租户。升级安全边界、需要联网/包安装、真实全栈集成、跨实例恢复或执行中崩溃重放时重评 Docker/远程沙箱。维护责任为实践维护者；移除独立执行 Workflow 和脚本即可退回提案模式，保留 JSON/源码/原生库作证据。人工身份仍是本地标签，无认证保证。

## 验收与完成报告

### 2026-11-06 续办修复

维持原生Workflow/Store及文件检查点Adapter方案，不新增调度器或依赖。架构方案生成完成后将route恢复为all，只有新的架构阻塞/自检路由才触发重规划；completedTasks继续负责失败任务接续，避免额外维护平行进度状态。执行身份作为Workflow状态保存并绑定方案及恢复hash，端点归一化后只存摘要；审批、接续和澄清入口共用校验，缺失身份的旧快照不能自动迁移或恢复。

评测入口校验合成证据与规范正文hash，真实产品来源仍从持久化产品批准派生。安全错误模块只从SDK异常读取白名单name/code/status/cause，抛给调用边界的是固定分类且不附原始cause；任务图语义错误使用SyntaxError归类。真实SDK503/连接重置复验发现原生默认error processor额外重试，因此同时设maxRetries=0、maxProcessorRetries=0，只保留已有Adapter的一次检查点重试。99/99实践回归、类型检查及OpenSpec strict通过；新真实模型批次与剩余边界见[续办记录](../../practices/mastra/evaluations/development/continuation-2026-11-06.md)。

数据结构沿用DevelopmentState，新增可空executionIdentity以读取历史结果，非空身份是继续执行的不变量。错误分类为有限枚举；角色返回值、身份校验和外部I/O分离，分别落实单一职责与边界隔离。复用原生路由和completedTasks而非增加恢复调度层，保持KISS；统一来源与身份校验避免审批/接续规则分叉。维护者仍为本实践维护者；出现外部副作用、多实例或升级旧快照迁移需求时重评原决策。

实现与回归已完成，48项旧版真实模型 pilot、修复版完整48项及两例歧义补验均记于[观察报告](../../practices/mastra/evaluations/development/observations-2026-11-06.md)。修复版为24次交付断言通过、18次澄清、6次模型/网络失败，人评0/48，能力未准入；原始存在伪造检查路径的批次不能作为 Agent 能力准入依据。重跑后补充的架构阻塞上下文仅完成确定性回归，未单独验证真实模型收益。
