## 问题与约束

本地不可变归档未推送且产品前序正文、项目文件和历史评审重复注入模型。角色交付必须有远端版本回执；同步失败不能重复生成。审批仍由原生 Store 拥有，正文和源码的当前运行校验兼容历史状态；模型输入不得默认展开所有材料。

非目标：自动合入主分支、自动部署、迁移历史 Run、赋予 Agent Git/shell 权限、跨实例同时推进同一 Run。完整源码执行仍由原有候选环境拥有；开发阶段额外归档实际候选源码，不能将交付副本等同代码合并。

## 决策与数据契约

采用 Adapter 与 Decorator：宿主对明确投影文件使用独立临时 index 创建 commit，推送 codex/workflow/<rootRunId> 分支；不切换用户工作树、不提交用户暂存区、不强推。回执绑定 branch、commit、文件路径及 SHA256。固定 origin 经原有校验；pushurl 必须等于 origin，禁止被配置转向其他目标。网络失败仅暴露脱敏错误。

成功输出先保存本地恢复检查点，再归档和同步；失败重启同一节点时复用该输出。同步失败通过原生暂停与工作台同步关口恢复，成功才返回下游。同步回执不属于人工批准，不能伪造批准。

模型输入通过按调用生成的只读 manifest 访问：大字符串、数组/对象折叠为固定散列引用；工具只接受本调用登记 ID，按片段读取，限制单次和累计返回字节。完整内容在宿主保存或已有远端产物中，引用不能修改权限。上下文预算在模型调用前执行，超限明确失败，不静默截掉批准或验收条件。

## 实施计划与兼容

路径：delivery/repository-assets.ts、delivery/remote-handoff.ts、delivery/task-context.ts，产品/开发/测试/发布模型调用入口与测试。无新增 npm 依赖。历史 CLI 未绑定业务仓库时保留本地行为；Studio 绑定仓库的业务产物启用远端交付。fixture 不推送真实远端。

Workflow 新增可选版本回执；现有正文和源码字段暂作为旧审批/候选校验的兼容快照，不能宣称整个持久化状态已仅含引用。下一阶段如需移除这些字段，需同步升级审批读取、源码恢复与旧 Run 迁移；不得通过删除历史状态破坏恢复。

维护者负责原生恢复路径和 Git 凭据；并发同 Run、多实例或上下文质量退化时重评队列/锁、检索与状态迁移。退出时可继续读取 Git 文件及回执，停用同步 Adapter。

## 历史同步失败的受限恢复（2026-11-08）

接受适配既有私有生成缓存与原生 Time travel：仅对未实施、尚未批准技术方案、已保存业务阻塞方案的 architecture 同步失败开放恢复。校验当前批准产品、输入、身份、方法、源码检查点及原生成记录；缺缓存或归属冲突拒绝恢复，不重新生成代替同步。兼容旧缓存正文，后续网络失败进入已有 repository-sync 暂停关口。UI 区分模型调用额度、资料读取预算和同步失败，不用“无入口即预算耗尽”推断原因。原生事实、源码权限及审批契约保持不变。

## 按阶段远端路由设置（2026-11-09）

远端交付从单一 HRM 目标扩展为服务端目标注册表与页面阶段策略：`MASTRA_REMOTE_SYNC_TARGETS` 只在服务启动时解析额外 `{ id, label, root, origin }`，并与默认 HRM 目标共同构成白名单。工作台只读取目标 ID/标签，能为产品、技术方案、开发与评审、测试、发布配置开关和目标 ID；不能传入本地路径、Git URL、凭据、分支或推送参数。设置原子保存在实践数据目录的 `remote-sync-settings.json`，不属于 Workflow/LibSQL 的审批或恢复事实。

Decorator 依据原生步骤 ID 映射阶段，并在执行时重新解析当前授权目标：关闭或未知阶段不产生 Git 副作用；启用时仍校验 checkout 是真实 Git 根目录且 origin 与登记值匹配，再沿用既有隔离 index、不可变投影、回执和同步失败暂停。设置只影响之后进入的节点，不改写历史 Run、既有检查点或已提交回执。初始策略将所有阶段指向第一个登记目标，保持现有单 HRM 项目语义。

此版本不实现动态开发角色（前端/后端/工程）各自分仓。现有开发节点可能在一个 Agent 团队步骤内汇总多个角色，缺少独立角色交付边界；仅增加下拉框会造成“已隔离”的错误承诺。后续必须先产出稳定角色路由键和逐角色交付节点，再扩展注册表和 UI。验证覆盖实际产品、架构、开发、测试、发布步骤映射、禁用阶段和未授权目标拒绝。

后续将仓库字典独立为“项目仓库管理”页：字典保存在本实践数据目录、与阶段策略和 Workflow 事实分离。操作者可新增、编辑或删除目标，但保存前服务端要求每个 `root` 已是本机 Git 根目录、`origin` 精确匹配不含凭据的 HTTPS 地址；删除仍被启用阶段引用的目标会被拒绝。环境变量继续仅作为首次启动的初始字典。管理页不自动 clone、切换工作树、改写业务源码或推送；阶段同步仍沿用既有隔离 index 与暂停恢复契约。

## 预算不足的可继续交互（2026-11-08）

采用既有原生 recover-development 暂停/恢复，不增加调度器。调用额度和资料预算分开记录：前者明确追加调用次数；读取、消息上下文、目录预算触发具名诊断，即使模型吞掉工具错误也不得当作已完成结果。资料预算按人工确认逐级提高，每级翻倍、最多4级；到上限仍保留重试/停止入口并说明需缩小材料，不能承诺任意模型容量。恢复绑定当前版本、源码检查点及故障类型，拒绝跨类型追加、跳级或降低；重新调用当前阶段而非恢复模型内部token位置。只读资料权限不扩大，已成功任务、调用消费及审批保持。验证以原生暂停、重开、拒绝旧令牌、回滚与再次继续为准。

预算续跑实证：221项回归通过；追加后的原生暂停诊断字段另经27项开发回归。隔离fixture页面通过填写确认人和二次确认完成48KB→96KB资料预算续跑，以及72次用尽后自定义追加10次续跑，均停回方案批准，未自动实施或影响真实业务Run。已保存原生预算类型、触限字节量、追加档位和人工决定，新增字段可空以兼容旧检查点。

### 2026-11-08 资料定位与分片策略

在现有 Mastra toolsets 适配内增加分页分片目录与字面关键词定位，继续使用原生工具循环和 Processor。资料策略独立为版本化 TypeScript 配置，分片纯函数不依赖 Workflow、Git 或模型；仅注册固定策略，不加载配置指定的可执行脚本。相较全文自动摘要/RAG，当前固定版本原文需要精确位置与完整性，暂不引入向量库或有损摘要；相较仅增加预算，目录定位能减少无关读取。维护者为 Mastra 实践维护者；替换点为独立分片函数，未来超大资料/跨调用分批综合需另行验证，不宣称当前实现自动多轮综合。

实践内部契约：默认段落边界分片，也支持固定长度；原文不改写，片段为 UTF-16 offset/end 半开区间。目录与搜索分页、有返回数量及字节上限，正文仍通过原有读取工具并累计计量。配置只影响资料装配，不改变文件权限、调用次数或审批；预算级别保持0–4兼容。配置随版本发布，不支持运行中热更新。原生 Workflow 检查点不新增第二状态源。此变更不修改探索主线 OpenSpec 契约。
