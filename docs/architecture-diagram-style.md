# 架构图视觉与表达规范

## 目标

当前项目的架构图默认采用“模块、关联、边界、路径摘要”四层表达。视觉参考为清晰的白底工程图：模块使用具名框和简洁图标，关系使用带文字的箭头，职责域使用实线或虚线边界，底部单独提炼主执行、持久化和观察路径。

图的目标不是把所有名词放进一张画布，而是让读者能够依次回答：有哪些模块、谁调用谁、数据归谁、哪些是旁路、当前能力到哪里为止。

## 默认构图

1. 左上角使用“英文主题 + 中文范围”标题，副标题说明当前态、目标态或具体场景。
2. 主体中央放置本图的核心拥有者，例如 Agent Runtime；内部循环或阶段必须显式编号。
3. 左侧优先放输入准备、上下文或模型调用链，右侧优先放持久化、外部能力与观察旁路。
4. 边界框标题必须说明职责域，不只写技术名；当前进程、独立服务、事实源和旁路要能被直接区分。
5. 底部使用 2-3 个路径摘要复述最重要的端到端关系，默认覆盖主执行路径、持久化/恢复路径和实时输出/可观测路径。
6. 一张图只回答一个主要问题。单会话生命周期、Context Planner/Memory Manager 内部、多会话/多端同步过于拥挤时，拆成多张同风格图，不把所有概念塞入总图。

## 模块与边界

- 模块名优先使用稳定英文代码概念，并补充中文职责，例如 `RunEventSink / 易失生命周期事件`。
- 实线外框表示当前主职责域或独立运行边界；虚线外框表示观察旁路、准备链或逻辑分组，不暗示新的事实源。
- 当前、受限切片和 TODO 必须显式区分。未来能力不能与当前运行态使用相同完成语气。
- 六个架构区域是能力归属，不是请求步骤。平台控制面和治理区域不应被画成每次业务请求都同步经过。
- SQLite Conversation Store 是当前 Session/Run 事实源；`RunEventSink` 和 ChainTrace 都不能画成可恢复业务事实源。
- 模型连通性测试链只用于 smoke test、CI 和排障，不进入业务主链架构图。

## 关联语义

- 蓝色实线箭头：主执行调用或确定的数据流。
- 反向实线箭头：结果回填、事实加载或恢复。
- 紫色虚线箭头：实时观察、Trace、策略或其他旁路关系。
- 箭头旁必须写动作，例如“原子写入”“加载事实”“受权执行”，避免只靠位置猜关系。
- Event、Trace、Session 和 Delivery 使用各自的名称，不用一个通用“事件流”覆盖不同生命周期。

## 视觉规范

- 默认白底、蓝色主线、深灰正文；持久化使用青绿色，受管外部能力使用琥珀色，观察旁路使用紫色。
- 不使用渐变、装饰性阴影或大面积氛围背景。边框 2-3px，圆角不超过 8px。
- 图标只用于快速识别模块，不替代模块名；保持同一线性图标语言。
- 关键正文在常用分享尺寸下不得小于 11px；长说明换行，不与箭头或其他模块重叠。
- 源文件使用 SVG，分享版本使用同名 PNG。资产统一放在 `docs/assets/`，SVG 是可编辑事实源。
- 新增或替换图后，必须在所属文档和 `docs/README.md` 中提供入口，并核对 PNG、SVG 的内容一致。
