# Nacos 产品资源与 live 产研流程：已验证事实和待处理问题

本文汇总 2026-11-17 至 2026-11-18 的本机隔离验证。产品评测使用合成需求、隔离候选目录和 `evaluation-policy` 审阅标签；这些标签不是认证身份，也不是实际业务负责人的验收。Mastra Store 持有 Workflow、审批与恢复事实，本报告是说明性记录。

## 已验证的事实

| 项目 | 证据与实际结论 |
| --- | --- |
| Nacos 连接与权限 | 本机持久化 Nacos 3.3.0 已发布并读回两个候选角色 Prompt 和 113 项 Skill；普通账号能读取这些资源，尝试创建合成 Prompt 返回 403。这是单机隔离实例证据，不代表生产角色权限或人工内容审核已完成。 |
| Run 资源冻结 | live Run `365b4224-576b-43bd-bb9f-3254a1ef4aa5` 的初始化快照包含两项 Prompt、113 项 Skill 和审查角色三项 Skill 绑定；产品阶段实际观察到 `skill`、`skill_read` 工具调用。冻结和工具调用不代表模型按方法获得正确业务结论。 |
| 恢复摘要问题 | `invalid-output` 故障记录中的 `diagnostic` 与 `modelCall` 在生成和持久化时顺序不同，原摘要以 JSON 字段顺序计算，因此相同状态恢复失败。已统一新记录顺序，并仅在完整状态按旧顺序精确匹配时兼容历史摘要；实际内容或源码检查点变化仍拒绝恢复。该修复已提交为 `3660291`，确定性回归与真实 Run 的后续重试均越过原摘要错误。 |
| 审批事实与历史正文 | Run `e7daa3cb-2566-44dd-a38e-c4b326e2e6a3` 存在同版本产品批准，但原文仍写生成时的待审批；研发误将其识别为业务阻塞。现有工作区修改把匹配版本的 Workflow 事实与原文分开提供给模型，并明确技术方案生成、就绪审查和独立审批的顺序。它不能自行创建审批或授予实施权限。 |
| 问题卡片 | 开发阻塞必答必须关联实际阻塞并标记阻塞研发，可选问题不能关联阻塞。结构化输出契约已明确分类并在有阻塞时要求问题非空；宿主仍逐项验证所有业务阻塞。原 Run 经恢复后实际生成合法卡片，保留并经评测规则确认修订稿。 |
| 就绪报告 | 宿主要求逐项引用产品原文与任务。原 Run 的修订稿产生 273 个非空行锚点及一个任务，模型数次遗漏覆盖；现有工作区修改区分固定的覆盖错误诊断，并向结构化输出声明允许引用及最小数量。真实 Run 随后生成覆盖清单并通过结构校验；不能据此断言逐项语义已人工审查。 |

## 仍未完成的事项

1. **原 Run 未完成研发。** 其就绪报告判定 `FAIL`：一项误将技术方案审批作为当前就绪前置条件；另一项指出公开 smoke 缺少 Unicode、边界、错误映射与输入不变性的可复现检查。后者是有依据的验证缺口，不应自动标为已通过。原 Run 最终是 `success` / `blocked`，没有完成实现、独立测试或部署。
2. **最后补充的就绪阶段审批顺序尚无 live 成功证据。** 曾按同版本批准、未实施、执行身份及源码检查点核对后尝试对原终态受控复核，没有观察到节点重新执行；不修改旧报告或伪造 PASS。
3. **新验证已中断。** Run `2f334d46-9f23-44f1-8bfe-796b523357d2` 在用户要求不再开启新 Run 后中断了启动它的评测进程；最后只读快照仍显示 `running`，没有观察到终态，不可称为通过、失败或已经安全取消。是否及如何恢复需另行核对原生状态与调用进程。
4. **Nacos 还没有接管全部产品提示词。** 两个角色 Prompt、指定版本 Skill 和角色子集已接入；阶段、模式、阻塞回流等提示仍有代码内文本。产品 Skill、Prompt 源资产位于 `nacos-resources/product/`，已发布的是本机候选版本，不代表其他机器自动同步或生产发布。
5. **真实业务交付尚未验收。** 测试计划、真实测试结果、部署和健康回执分别需要真实证据；评测自动回答不代表外部发布。MCP、A2A、生产多实例恢复及真实模型质量继续保留为后续范围。

## 已确认的边界与后续处理

- 用户已确认由宿主执行角色和工具权限上限、结构校验、人工审批与事实、资源版本和摘要、调用预算五类边界。提示词文字本身不因描述这些规则就必须写死。
- 优先修复审批事实和阶段事实传递；对历史 Run 不删除阻塞、改写就绪报告或制造批准。若以后需要继续已终止的 Run，应先明确支持的恢复路径和安全前置条件。
- 结合这次真实数据复核“每个非空行都要求覆盖”是否合理：标题、代码块和状态文案也会成为锚点。任何改动都要保留真实需求、验收和任务的可追溯性，先设计契约和回归，不能直接补齐未被模型核实的覆盖事实。
- 为合成需求增加独立可复现的边界验收，以区分已执行测试和模型建议；不能修改已批准检查文件或把未运行的检查报告为通过。
- 跨电脑复用依靠 Git 中的资源唯一来源与精确版本；每台机器仍需可用的 Nacos、注册、持久化与权限设置。后续事项见 [Nacos 产品资源接入待办](./nacos-integration-todo.md)。
