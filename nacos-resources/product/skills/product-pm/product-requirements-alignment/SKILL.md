# 产品需求判断与持续对齐

围绕同一需求闭环推进：识别目标与证据 → 明确业务选择 → 同步需求 → 复核交付。澄清与审稿是辅助行为，按任务规模选择步骤，局部修改只处理实际影响。

## 适用边界与输入

- 适用于产品职能在不同业务项目中的需求工作；读取目标项目的协作规则、需求入口、最新决策和当前任务，不依赖此前聊天记忆。
- 可从一句诉求、已有PRD或待接续任务开始。先利用已有证据；目标读者、用途、交付形式、范围及完成标准能从上下文确定时，直接沿用。
- 用户指令及项目权威规则优先。规则冲突按项目权威顺序处理；项目未规定时，先核实冲突来源和确认状态，不能自行决定哪条业务政策生效。
- 只沉淀方法；角色、目录、状态、阈值、审批政策、数据保留期与工具契约由目标项目决定。技能不授予提交、推送、发布或发送消息权限。

## 推进流程

1. **定位阶段与变更**：识别发现问题、形成范围、细化需求、交付评审、实施验收或效果验证。Git项目先检查 `git status --short`、`git diff --stat`、`git diff --name-status`，保护无关修改；其他环境使用可用版本记录。沿当前任务补读资料，避免全量加载。
2. **检查业务闭环**：沿实际路径核对角色、对象、入口、输入、权限、状态、结果、异常、依赖与验收。新需求或模块复审读取[交接检查](references/handoff-checks.md#功能完整性检查)；页面、公共规范或指标变更只读取其中对应部分。内部已有定义但正式交付遗漏时，主动补齐已有依据的需求。
3. **区分补齐与决策**：表达、引用、导航、重复及已确认规则的验收缺口直接修正。业务范围、授权、状态或成功门槛有新选择时，先检索已有答案，再集中给出推荐、理由、影响及最少必要问题。暂停依赖该选择的部分，继续其他已确认工作；不把建议写成已确认政策。
4. **同步关联定义**：定位本次规则的权威源，沿决策 → 公共／模块规则 → 字段、页面、图示 → 任务与提醒 → 验收及正式输出核对。只同步实际受影响的内容，保留有效约束、稳定引用和工程追踪；公共规则保持唯一维护位置。
5. **复核实际交付**：正式编写与审稿读取[交付写作](references/delivery-writing.md)。按首次接触的研发／测试视角推演正常、条件不足、授权拒绝和本次相关异常。采用生成式交付时先改源、再生成并阅读实际输出；执行项目已有的引用、版本及生成一致性检查。图示有变更时检查语法与渲染。

## 任务路由与能力协作

| 当前任务 | 主要结果与边界 |
| --- | --- |
| 点子模糊、价值未明 | 明确用户问题、证据、关键假设、最小验证及失败判据；不越过范围确认直接实现 |
| 新需求、业务变更 | 形成当前结论或待选方案，同步实际受影响的正文、图示、验收和任务 |
| 正式需求与交接 | 沿既定结构输出连续、可执行的业务定义；无需读者拼接聊天或内部讨论 |
| “不专业／AI味重／再审查” | 先定位实际文件与版本，按问题类别复核关联正文和案例；不只换词或修单句 |
| 小幅表头或措辞修正 | 完成局部一致性修正及相关检查，保留已确认规则，不扩大为整包重写 |

项目已提供产品发现、PRD生成或测试场景等专项技能时，按实际缺口选用一个主方法；工具或技能不可用时继续完成可执行部分，并说明限制。本技能可以独立使用，不强制安装其他技能。

与PRD生成器的分工是判断证据、处理变更及维护一致性；与PRD准入审查的分工是形成和修正需求。用户仅要求生成固定模板或输出研发准入报告时，优先对应专项技能。项目既有准入门禁仍适用，不因本技能完成需求整理而自动通过。

## 输出与完成标准

- 在项目既有位置交付实际需求或修改，不为证明工作新增多份清单。正式需求表达当前目标、操作、条件、结果、异常与验收；候选方案、确认经过及制作过程留在协作资料。
- 交付报告按本次相关内容说明：已完成及原因、需业务选择的阻塞及影响、非阻塞依赖、验证证据和下一步。尚未解决的业务选择保留为未决项，不把该部分宣称为正式基线。
- 完成须有本次结论、关联同步、正文阅读、案例复核及适用预检证据；两种合理解释仍产生不同结果时，指出具体缺口。
- 区分需求输出、联合交接、实现验收与效果验证。结构校验和文档推演仅证明其检查范围，不证明未来任务表现或真实产品效果。

## 维护与兼容

- 适配基线：Agent Skills的 `SKILL.md` 与相对资源引用；不绑定业务版本、框架、MCP或客户端专用提问工具。可用文本、文档或Git材料执行；自动检查工具按目标项目提供。
- 维护责任由 `metadata.author` 标识；重大方法变更由产品职能评审，具体业务政策由目标项目授权决策者确认。入仓按仓库 `product-pm/` 审批规则执行，实际审批账号以GitLab配置为准。
- 调整路由、决策边界或核心流程后，按[验证案例与记录](references/validation-cases.md)执行代表性任务，记录实际产物及遗漏；优先修通用机制，避免逐次追加全局禁令。
