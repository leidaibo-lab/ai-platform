# 设计草案

本设计为待实施方案，当前主线仍使用 `product-development` 作为业务入口。任务和验收进度见 `tasks.md`。

## 输入与来源

独立团队 Run 使用 `team-run-input.v1`，以团队、项目、迭代、来源引用、预算和团队专属载荷表达请求。服务端解析权威来源并在 Mastra Store 冻结输入、项目身份和版本；客户端不能提交审批结论、候选路径、任意 Git ref 或执行命令。

产品消费原始需求或经确认的材料；研发消费已批准的产品产物或经确认的输入包；测试消费研发交付和固定候选；交付消费同版本 QA 放行及正式规格。输入包的登记、验证与人工确认需要在实现前进一步细化，不能把文件或登记表当作审批事实源。

## 团队运行与隔离

各团队使用独立 Mastra Workflow 和 Run。项目选择、方法版本、预算、暂停与恢复沿用平台约束。团队专业状态留在各自 Workflow，公共信封只作投影；测试返工经版本化研发 Port 交接。

测试独立运行须复制并核验来源候选，确保返工不会改动来源 Run；交付核对 QA、候选和正式规格的来源关系后才使用受控 Git/MR 端口。来源 Run 与新 Run 的正式规格分支、候选身份及回执关系须明确设计并通过恢复与并发验证。

当前项目绑定、资产归属和原生恢复保护包含主流程 Workflow ID 与初始化路径的假设。实现独立入口前，应扩展这些校验，并覆盖 Studio 原生入口及多项目隔离；不能直接将团队子 Workflow 暴露给客户端。
