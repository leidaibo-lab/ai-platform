## 当前状态

本变更为待实施任务。远端主线尚未接入独立团队 Workflow、来源解析、配置入口或团队级回归；本任务清单的勾选只以合并到主线并完成对应验证为准。

## 1. 输入契约与来源

- [ ] 定义并接入 `team-run-input.v1`：团队、项目、迭代、来源引用、预算及各团队专属载荷；拒绝未知字段和伪造审批、候选、Git 版本或执行命令。
- [ ] 从 Mastra Store 按来源 Run 的实际 Workflow 身份读取已完成的产品批准、研发交付及 QA 放行；核对来源 Run、项目、内容散列与批准版本。
- [ ] 从绑定项目仓库重读正式规格 Git 回执并验证文件散列；支持主流程和独立团队 Run 的上游来源，拒绝跨项目或身份漂移。
- [ ] 设计预先提供的输入包登记和确认入口：明确材料类型、适用团队、验证结果、确认人、版本、失效条件与撤销方式；交付必须使用可核实的 QA 证据。
- [ ] 在独立 Run 初始化时冻结规范化输入、来源证据、项目 revision、Adapter profile、方法目录及适用预算；恢复时从 Store 重验绑定。

## 2. 平台与团队 Workflow

- [ ] 泛化项目绑定和原生入口保护，支持各独立 Workflow 身份、初始化路径与 Store 查找；覆盖 start、resume、restart、timeTravel、流式及异步入口，保持历史主流程恢复兼容。
- [ ] 装配产品独立 Workflow：原始需求或确认材料进入现有澄清、写作、独立审查与人工批准；完成后停止于产品团队边界。
- [ ] 装配研发独立 Workflow：从已批准产品输入与登记工程启动，保留项目范围和架构审批；处理产品来源 Run 与新 Run 的规格回执和分支归属。
- [ ] 装配测试独立 Workflow：读取研发交付并校验候选，建立独立候选副本；测试返工经 `rework-request.v1` 与研发 Port 处理，不能修改来源 Run 的候选或状态。
- [ ] 装配交付独立 Workflow：核对产品、研发、测试规格、同版本候选与 QA 证据；受控创建 MR 并记录回执，保留失败重试与幂等校验。
- [ ] 明确独立团队之间的结果引用、缺陷回流、预算继承和新 Run 与来源 Run 的分支关系；Mastra Store 保持审批与恢复事实源。

## 3. API 与工作台

- [ ] 提供项目隔离的来源发现、输入包准备与确认、独立 Run 启动、状态读取及人工关口恢复 API；客户端只提交登记标识与版本化来源引用。
- [ ] 工作台提供团队选择、来源选择或材料接入、缺项提示、启动及运行记录；各团队展示自己的证据、审批和阻塞。
- [ ] 恢复前核验当前暂停版本与输入身份；重复提交、丢失响应、并发启动和跨项目访问有明确拒绝或对账结果。

## 4. 回归与验收

- [ ] 产品团队独立回归：澄清、写作、批准/退回、非法来源和恢复。
- [ ] 研发团队独立回归：批准来源、项目范围、真实受控检查、候选隔离、权限和预算。
- [ ] 测试团队独立回归：来源候选、用例批准、登记检查、质量门、返工 Port 与来源候选保持不变。
- [ ] 交付团队独立回归：缺失或漂移 QA 证据拒绝、同版本放行、MR 重试和远端端口替身。
- [ ] 多项目并发、重启恢复、原生入口绕过、来源漂移、输入包确认及历史 Run 兼容回归。
- [ ] 保留全链路回归，验证产品→研发→测试→交付及跨团队返工；团队回归不能代替全链路结果。
- [ ] 完成 OpenSpec 严格校验、类型检查、工作台构建及上述回归；记录命令、结果和实际未验证范围。
- [ ] 分别记录 fixture、真实模型、真实远端 MR 和生产验收证据，不将任何一种替代另一种。
