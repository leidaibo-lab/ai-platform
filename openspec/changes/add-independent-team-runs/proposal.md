## Why

各专业团队目前只能作为 `product-development` 的嵌套 Workflow 运行，不能单独启动和复用团队级验收。下游团队依赖上游已批准的产物、工程版本、候选源码和证据，直接暴露嵌套 Workflow 会绕过输入来源、项目绑定和审批契约。

## What Changes

- 定义版本化、规范化的团队 Run 入参，统一表达目标团队、项目选择、来源引用、预算和团队专属输入。
- 为产品、研发、测试和交付提供独立 Run 入口；下游输入可从已保存 Run 选择，或从受控接入入口预先提供并经校验和人工确认。
- 冻结来源 Run、产物版本、项目与 Adapter 身份；服务端从 Mastra Store 和登记仓库解析权威内容，不信任客户端提交的审批、源码、散列或远端身份。
- 为每个团队建立独立回归套件，同时保留全链路交接和返工回归。

## Impact

- 影响团队 Workflow 装配、intake API、项目绑定、工作台团队入口及回归测试。
- Mastra Store 继续持有执行、审批与恢复事实；团队专业状态仍由各自 Workflow 持有。
- 既有 `product-development` Run 输入和恢复图保持兼容；独立 Run 使用新的团队入口身份，不重写历史快照。
- 真实 MR 交付仍必须依赖同版本 QA 放行证据和登记项目，不接受手工声明通过。
