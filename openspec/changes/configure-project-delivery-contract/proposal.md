## Why

多项目工作台已经能按项目 ID 绑定已登记的 Git 仓库，但各业务工程的需求、产品、源码、测试和规则落点仍散落在固定路径与 Adapter 假设中。阶段同步开关还允许关闭正式交接，使下游缺少必须的业务上下文。

## What Changes

- 为已登记业务工程提供项目级交付契约配置；仓库身份继续来自服务端项目注册表，页面只选择项目，不重复配置仓库地址。
- 配置需求、产品规格、开发代码、测试用例和工程规则的仓库内落点，并在服务端校验相对路径。
- 正式产品规格交接成为必需门禁，不提供关闭选项；交接失败时下游暂停在可恢复点。
- 每个 Run 冻结项目交付契约版本身份；恢复和下游读取沿用该版本，配置变更只影响新 Run。
- 首次接入时检查契约文件和目录缺口；平台可按配置准备缺失的目标目录与模板，生成的工程规则/Adapter 仍须负责人确认后才可成为有效项目基线。

## Impact

- Mastra Store 仍是 Workflow、审批和恢复事实源；仓库仅保存经批准的版本化项目契约及阶段交付副本。
- 影响 intake 项目配置 API、正式规格路径校验、产品交接、下游回读和工作台设置页。
- 已存在的 Run 按其冻结的历史绑定恢复；不得将历史回执重解释为新路径配置。
