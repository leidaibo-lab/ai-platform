# 应用实践协作规则

本目录用于按目标项目原生方式学习和构建应用。先读[集合入口](./README.md)和目标实践的 README，再读该项目当前官方指南。

## 架构与范围

- 保留目标项目原生入口、目录、Agent、工具、状态和执行模型。不要默认导入根目录 `src/runtime/`、Store、GatewayClient 或已有实验 Adapter。
- 根目录六区域架构和唯一 Runtime 主链约束探索实现，不要求本目录复制同一架构；比较时将它们作为一种设计选择解释。
- 本集合统一学习目标和证据方式，不建立统一运行时、跨框架数据库或强制 Adapter。
- 目标框架缺失的业务能力明确标识。需要补充业务逻辑时说明职责与维护成本，不因补齐后场景能运行就声称框架原生支持。
- 探索主线的集成/迁移需要独立决策；原生学习应用不以通过现有平台适配测试或替换现有 Runtime 为完成标准。

## 实践与证据

- 官方指南、安装包和源码优先；实现前核对当前 API，记录实际锁定版本，不能把未核实的示例当成已通过结果。
- 分别记录原生最小应用、业务场景、异常恢复、真实模型质量和生产验证；仅文档或固定数据测试不代表后续阶段通过。
- 每项比较说明架构差异、证据、收益、代价与适用场景。探索实现和成熟项目都可指出缺口，不预设探索实现是标准答案。
- 原有 `experiments/pi-agent` 是适配探索，保留历史证据，不搬作 pi 原生实践，也不将其测试计数复制为本目录的结果。

## 配置与安全

- 每个实践独立管理依赖、lockfile、环境、端口、数据库与运行目录。新增执行入口前明确敏感配置及生成文件的忽略规则。
- 不读取、打印或提交真实密钥；不复制根目录 `.env`。只提交无真实凭据的配置样例。
- 代码执行环境、外部写操作和部署权限按场景明确；原生运行不豁免授权和数据保护要求。
- 中文协作、函数紧邻注释、JSDoc 数据结构、设计原则及 `type(scope): 中文说明` 等全仓库规范继续适用。
