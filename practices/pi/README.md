# pi 原生应用实践

- 方向：应用实践。
- 当前状态：已建立学习入口；未在本目录安装依赖或建立原生应用。
- 版本：尚未选择；不得把历史适配实验中的版本和结果直接当作本实践证据。

## 学习目标

按照 pi 自身的使用方式理解 Agent、编码任务、工具、上下文和任务生命周期；再根据实际覆盖能力选择应用场景，与探索实现和其他原生实践比较。

先核对官方入口和当前推荐使用方式，不要求 pi 套用 Mastra 的 Workflow 抽象，也不假定它原生覆盖完整产研协作流程。框架能力、额外组件与需要补充的业务机制分开记录。

## 与已有 pi 实验的区别

[`experiments/pi-agent`](../../experiments/pi-agent/README.md) 测试 pi 能否适配本项目已有的 Runtime、GatewayClient、SQLite 事实、恢复和验收契约。它属于探索方向，历史代码、记录和测试结果留在原处。

本目录研究 pi 原生应用应怎样构建和运行，不默认导入 `pi-gateway.mjs` 或探索 Store。旧实验可用于提出比较问题，但其中的适配成功、局限或测试计数，不能作为本目录原生应用的运行结果。

## 实践顺序与比较问题

1. 从官方推荐入口建立原生最小应用，记录实际选择的组件、版本、依赖和配置。
2. 核对消息、工具执行、上下文与任务状态的原生所有权和扩展方式。
3. 选择[共同业务问题](../README.md#当前共同业务问题)中适合的阶段，运行真实任务并记录交付物；能力缺口直接说明。
4. 验证实际支持的中断、恢复、取消与失败行为，不把独立附加组件的能力归为所有组件都具备。
5. 比较原生方案、已有 pi 适配实验和探索实现的差异；说明收益、代价、适用条件和证据层级。
