# 首稿人工审阅

组织者只交付本目录，保留 organizer/ 分组映射。按 reviews.json 的随机顺序独立审阅 documents/<sampleId>.md，未拿到或未生成的稿件留空。不要先看另一组的同题稿或比较报告；同题重复审阅可能产生学习效应，无法保证完全盲法。正文的方法引用也可能暴露分组，不要为隐藏分组删除业务内容。

从首次阅读原始诉求和产品稿开始计时，完成量表和首稿放行决定后停止。仅计主动审阅时间，暂停时停表；不含模型生成、返工和第二轮审阅。reviewSeconds 以秒填写。每一份填写 reviewer，先固定首稿决定，再看另一稿；后续返工通过不能覆盖首稿决定。fixture 是脚本稿，只验证管道，不评模型质量。

按 rubric.json 逐项填写 coverage：

- met：在正文中正确保留，或将未决事项准确列为待确认。evidence 引用正文位置和依据。
- missing：没有涉及必要规则、场景或待确认问题，记录具体遗漏。
- incorrect：虽提及但写错、相互矛盾，或把未决规则变成已确认，记录错误依据。

每项 evidence 必填；额外问题写入 additionalDefects，标记 critical/major/minor。critical 为越权、越界或关键业务规则错误；major 为阻碍实施/验收的重要缺口；minor 为可局部修订的表达问题。只有没有未解决 critical/major 问题、可进入下一阶段时 firstPass 才填 true；否则 false。未决业务决定阻碍实施时应不通过，不因模型正确提出问题而自动通过。量表逐项全对也不自动表示能放行。

所有指标默认 null。未审、不确定、系统失败都不要填 0 或 true。组织者汇总时不完整的人工表仍为 pending，生成失败单列，不从计划中删除。
