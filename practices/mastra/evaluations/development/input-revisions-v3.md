# 研发评测公开输入 v3 修订说明（2026-11-06）

## 触发与规则来源

v2 完整48项重跑出现18次需求澄清，其中4次为两条歧义任务各两轮的预期结果，另14次发生在实现任务。后者集中于身份字段、幂等返回、文件校验顺序、安全ID、迁移非法输入及字段冲突、分页解析边界。这14次不能直接判作 Agent 能力失败：原规格存在缺口，必要提问与过度阻塞也仍需独立审阅。原始事实见[实测观察](./observations-2026-11-06.md)。

本版为22条实现任务公开补齐输入域、字段规则、错误策略和域外责任，目的是使执行者能够依据公开任务判断何时实现、何时澄清。新增规则属于**评测组织者定义的合成契约**；既不是从真实HR/财务产品确认中提取的批准事实，也不代表所有业务应采用这些默认值。执行者不得将此处选择外推到未批准的真实项目。

修订依据是公开任务的缺口与已观察到的澄清类别；组织者以现有 oracle 做一致性核对，未将其隐藏调用、样例参数、断言结果、人工评分依据或答案实现提供给被评 Agent。真正未定的业务规则仍由 amb-01/amb-02 检查，不通过自动选择默认值消除歧义。

## 公开契约补足范围

| 类别与案例 | 本版补齐的范围与取舍 |
| --- | --- |
| CRUD：crud-01、crud-02 | 创建ID、所有者和时间由调用方保证有效；标题使用trim和Unicode码点长度。资料卡仅做投影，明确时区空值，不重新发明身份或时区校验。 |
| 授权：auth-01、auth-02 | 明确租户/组织边界优先、角色组合、发票提交人字段、pending状态和缺失身份拒绝策略；组合仅是合成授权规则。 |
| 事务并发：tx-01、tx-02 | 明确priorOperations只表示已成功操作，重复受理保持当前库存而不重放历史数值；非正数量先拒绝，再判幂等和库存。租约明确同owner续租、空owner或过期领取，不宣称真实锁或数据库原子性。 |
| 异步重试：async-01、async-02 | 明确尝试计数、精确错误码、上限与退避基数；任务重排保留额外字段，输入记录校验交调用方。 |
| 文件存储：file-01、file-02 | MIME类型先于大小校验；范围包含0和5MiB。安全ID由调用方提供，key按MIME扩展生成，不含原始路径。下载规则明确组织和角色边界。 |
| 数据迁移：migration-01、migration-02 | 员工姓名以最后一个ASCII空格拆分、不额外trim，派生字段覆盖同名旧字段。工单自有status字段存在即优先，无效值不回退旧state；非对象返回null。这些是组织者的合成迁移选择。 |
| API契约：api-01、api-02 | DTO仅投影公开字段。查询page/limit只接受十进制正整数字符串；page需为安全整数，limit超100回默认20而非截断，各字段独立回落。 |
| 缺陷修复：bug-01、bug-02 | 金额限定有限整数分和三位大写ASCII币种代码，不查询ISO清单；日期明确有效公历、显式时区和UTC日期闭区间，无效输入拒绝。 |
| 诊断：diag-01、diag-02 | 排序输入为有限优先级并保持稳定和不可变；分页pageSize无效抛RangeError，totalItems有效性由调用方负责。 |
| 安全：sec-01、sec-02 | 资源ID安全字符集由上游保证，仅取basename最后扩展；HTML编码仅限文本节点，其他Unicode保留，不能外推到属性、URL或脚本上下文。 |
| 可访问性：a11y-01、a11y-02 | 明确错误空值、是否trim和属性省略；提交状态仅做纯展示映射，不隐式发起提交或重试。 |
| 需求歧义：amb-01、amb-02 | 保留原始任务、角色、候选说明和v2的no-op smoke；权限、锁定、审计通知及跨午夜/时区、待批换班、覆盖安排规则仍需澄清。 |

## 版本与复测约束

- `inputs.json` 从v2升为v3，只修改22个实现案例的 `requirement`。24例/12类、案例ID、角色、初始源码、公开smoke、返工次数、预期结果以及两条歧义需求保持不变。
- 本次不修改 `oracle.json` 的74条独立调用、`rubric.json`、准入门槛或旧运行记录，也不增加新的隐藏覆盖。测试固定非需求字段的资产散列，防止本次修订顺带改变公开检查或候选基线。
- v3重跑须使用新的输出目录和manifest，记录输入、代码、提示词及运行配置散列；保留v1/v2的所有结果，不回填成功项、不转移旧人工批准。
- 新旧结果的输入条件不同，不能把通过数差值直接解释为Agent能力提升；应分别报告交付、澄清、执行失败、独立断言和人工审阅状态。至少完成预定24例各两轮与独立人评后，才能按现有量表讨论85%试点准入。

## 尚未覆盖

本版仍是无外部依赖的Node.js ESM函数切片，未覆盖真实Next.js/NestJS/PostgreSQL/Prisma、浏览器、数据库事务、队列、Docker/CI或生产部署。它补齐任务规格，不等于全栈能力认证。现有人工评分尚未完成，本说明也不对Agent能力或准入作出通过结论。研发阶段自检和独立评测继续分离，未启动产品测试阶段或测试Agent。
