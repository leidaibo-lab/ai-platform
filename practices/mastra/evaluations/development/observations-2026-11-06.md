# 研发阶段工作流与能力评测观察（2026-11-06）

## 执行结果

本轮实现并触发了独立 Mastra 原生研发 Workflow：架构师生成技术方案、方案绑定输入和源码散列后等待确认、实现角色按文件权限读写、自检角色只读运行检查、宿主根据真实检查结果进行有界返工，最后生成研发交付包并结束。产品测试阶段未启动。

真实模型 pilot 按 inputs v1 运行24个案例各两轮、最多四路并发，共48个预登记 trial。模型响应记录为 `gpt-6-astra`；43个 Workflow 结束，35次交付结果的原始 judge 断言报告通过，8次停在需求澄清，5次失败。失败为歧义案例各两轮在启动前因输入缺少必需公开 smoke 而报错（4次），以及 file-01 第二轮模型调用90秒超时（1次）。每个计划项都保留在原 `trials.json`，未替换失败记录。

35次隐藏断言通过不是有效能力通过率：执行器当时使用同进程 Node 测试模式，候选代码可伪造 TAP 汇总并提前退出；另一个恢复门禁允许暂停期间更换输入文件中的 smoke 清单。这两处问题已独立复现。旧批次开始于 `2026-11-06T07:40:04Z`，不会重写或重新汇总成修复后结果。其原始报告和所有运行材料位于被忽略的 `.data/evaluations/development-live-pilot-2026-11-06/`。

生成的状态中，架构角色对缺失规则采取了澄清并停止实现。共8次澄清涉及发票提交人身份字段、重复请求返回值、文件安全 ID/校验优先级、迁移非法输入与字段冲突、分页 limit 解析边界等未定义规则。这些是输入规格缺口，不应记为实现 Agent 能力失败；是否提问完整仍需独立人工审阅。

已记录113次模型角色调用的响应用量，共约1,504,517输入 tokens、67,758输出 tokens；不包含失败前未返回 usage 的调用，因此这是可观测下界，不是账单或成本。48项 trial 的串行耗时相加约85分钟；四路并发的批次墙钟时间不用于角色效率比较。

## 修复与复验

- 恢复方案时同时比较持久化 Workflow 输入与重新打开目录得到的输入 hash；替换 `checkFiles` 会拒绝恢复且保留暂停点。
- Node smoke 移除 `--test-isolation=none`，使用默认隔离 worker，并要求 TAP 包含具名用例行；候选在加载时伪造 TAP 文本后 `process.exit(0)`会产生文件级通过但没有具名断言，因此不再放行。
- 歧义案例公开输入补上固定 no-op smoke，避免在生成方案前被项目 schema 拒绝；输入资产升为 v2。v1 记录仍用于还原批次事实。修复后的两例单独试跑中，一例正确要求澄清，另一例模型调用超时；这不是两例完整复测。
- 最终完整实践回归 **72/72**、类型检查、`git diff --check` 和 OpenSpec strict（1/1）验证通过。验证覆盖产品批准来源、方案hash、暂停后配置/源码漂移、跨进程恢复、真实工具读写、失败返工、文件权限和具名检查执行。

修复版24次交付的独立断言均通过，没有“已交付但独立断言失败”的记录；不能据此外推所有需求已满足。18次澄清中，4次为事前要求的两例歧义任务各两轮；其余14次涉及身份字段、幂等返回值、错误/非法输入策略和分页边界等未明确规则。模型两轮有行为差异，需要人工判断哪些问题是必要阻塞、哪些可从已有明确规范得到答案。6次失败为5次模型调用超时、1次上游 DNS 连接失败，分别为 api-01-r1、crud-01-r2、bug-01-r2、bug-02-r2、sec-01-r2 和 file-02-r2。失败始终保留在48项分母中。

修复版已保存90次角色调用的可观测 usage：1,045,753输入 tokens、51,451输出 tokens，响应模型均为 `gpt-6-astra`；失败调用缺少的用量未估算。没有带来源单价，不报告费用。两批输入/代码条件不同，不把结果差值解释为模型能力提升或下降。

独立复核还发现实现角色上报 `ARCHITECTURE_BLOCKER` 后下一轮架构角色原先收不到具体原因。完整重跑结束后追加了最多6000字符、含责任角色/轮次的最新阻塞证据上下文，避免传递整个历史；已补确定性回归。这项提示上下文修复晚于重跑 manifest，不能宣称已获本轮真实模型质量验证。检查器25/30秒超时预算已配置；模型超时路径确有观测，但 Adapter 达到预算后的强制终止路径未单独实测。

## 结论边界

当前能力状态为**未判定，不具备准入证据**。原始 live pilot 的检查通过值因执行器漏洞失去质量统计用途；修复版完整48项已结束，所有人工审阅均未填写，且存在6次运行失败和14次非预期澄清，不能宣称达到85%门槛。下一步应先独立审阅澄清和失败样本、完善公开需求规格，再按新版本固定条件重评；不能把隐藏答案回填给被评 Agent。

本轮仍然只验证离线 Node ESM 函数切片和固定 `node:test`，没有真实 Next.js/NestJS/PostgreSQL/Prisma 仓库、浏览器构建、数据库事务、队列、Docker/CI 或生产部署证据。macOS Seatbelt 路径有实测；Linux bwrap 未验。当前 judge 断言与候选源码在同一只读工作目录，不是抗恶意候选/防作弊服务。Node 隔离 worker 修复了已演示的提前退出伪造路径，但不替代容器级资源限制和可信评测进程隔离。
