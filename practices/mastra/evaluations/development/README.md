# 开发阶段能力评测资产

本套件与开发工作流共用真实 Agent 入口，目的是区分架构、实现、自检、返工和证据交付是否可执行，以及真实模型在具体小任务上的行为表现。当前为内部 pilot，不包含测试 Agent、独立测试阶段或生产发布。

[2026-11-06 实测报告](./observations-2026-11-06.md)记录旧版48项、修复版48项和两例歧义补验。修复版24次交付断言通过、18次澄清、6次模型/网络失败，人工未评，能力准入未判定。

当前输入资产为 v3；[v3修订说明](./input-revisions-v3.md)界定补充的合成输入规则及其能力结论边界。v3必须新建独立实测记录，不能覆盖或直接比较旧版本分数。

[续办记录](./continuation-2026-11-06.md)记录恢复/来源门禁修复及新v3完整48项结果（41交付、6澄清、1故障暂停，人评0/48）；旧中断批次不回写。新manifest额外保存不含凭据的executionIdentity及SDK/错误处理器零重试设置，避免把一次角色重试隐式放大为多次HTTP请求。

## 固定资产和隔离

- `inputs.json`：24 个独立案例、12 类各 2 个；只含任务、初始候选文件和公开 smoke。22 个实现案例使用无外部依赖的 Node.js ESM 函数切片；2 个需求歧义案例要求架构角色识别阻塞并停止实现。v1 歧义案例漏了必需 smoke 文件，已在 v2 修正；旧 live 结果保留该入口失败，不回写覆盖。
- `oracle.json`：组织者保管的输入/输出断言、人工审阅要求和歧义问题参考。Agent 工具不接收 oracle JSON；当前 judge 生成的 `acceptance.test.mjs` 与候选源码处于同一只读执行目录，不能防御会主动检查工作目录的恶意候选，只用于合作式质量摸底。
- `rubric.json`：与已确认设计一致的 100 分人工量表和硬失败标准。Agent 不得自行评分或宣称获得人工批准。

Runner 应先只用输入资产运行开发阶段；结束后在独立 judge 目录复制候选源码，再执行独立断言。oracle 不会在返工时回填给被评 Agent。由于候选执行进程能读取 judge 目录中的断言文件，该机制不是防作弊的隐藏测试服务。公开 smoke 可用于开发自检和返工，但只覆盖一条普通输入，不能作为完整需求通过依据。

每例最多返工一次，精确次数由 `maxReworks` 给出；角色清单显式区分 architect、frontend/backend 和 self-check。纯前端切片只检查可展示状态或转换函数，不代表真实 React 组件、浏览器渲染和可访问性验收；后端切片只检查规则，不代表真实事务、并发、多实例、对象存储或队列已通过。后续需要针对选定栈增加全栈仓库、数据库与浏览器案例，不将本套件分数外推。

## 结果判定

结果至少分别记录：未开始、生成失败、方案待确认、开发检查未通过、交付包已生成、隐藏断言通过/失败、人工待评。固定模型仅检验数据流与门禁，不得计入真实模型质量通过率。仅使用真实模型、生成成功、隐藏检查完整且人工审阅完成的案例才可以进入最终质量统计；总计划数、失败数和未评数必须同时报告，不能通过删除失败或待评案例美化成功率。

单例要求总分至少 80；需求追溯、功能正确性、开发自检、安全数据各维度至少达到本项 80%，并且无严重/高风险缺陷、无硬失败、所有硬性检查通过。首次受控试运行至少 24 个案例，每例重复两次，通过率至少 85%，且关键安全/数据案例全部通过。案例不足、重复不足、人工评分缺失或真实模型未执行时，准入结果保持未判定。

模糊需求案例的正确结果是保留阻塞并终止实现；其隐藏行为自动检查没有函数调用，不能把零条断言当作完整通过。人工必须复核是否提出了关键问题并说明影响。人工分数初始为 null；自动行为检查不能代填其他维度。

评测资产由本实践维护者维护；修改输入、公开检查、隐藏答案或评分标准时需调整版本、记录散列并重新运行，不复用旧人工批准。真实全栈仓库引入、业务变化或错误类型超出这些切片时重新评估案例及门槛。

## 执行命令

使用 Node.js 24+，在 `practices/mastra` 执行：

```bash
npm run check
npm test
# 固定模型只验证运行管道；预期不能解答真实案例。
npm run eval:development -- --rounds 1 --cases crud-01
# 使用本实践既有配置加载器取得凭据，48次完整计划，最多4个独立候选目录并行。
npm run eval:development -- --live --rounds 2 --concurrency 4
# 只读汇总已有结果；人工评分未填仍保持null。
npm run eval:development -- --report .data/evaluations/实际运行目录
```

默认串行、两轮；`--concurrency` 支持 1–4，实际值写入 manifest。显式 `--cases` 子集不能计为完整 pilot。每个案例通过同一 `openDevelopment`/原生 Workflow；评测由独立组织者规则批准架构，记录为 `evaluation-policy`，不冒充人工确认。输入/代码/依赖锁/提示词/量表散列写入 `manifest.json`；每个运行拥有独立 candidate、原生 `workflow.db`、judge 目录。`trials.json` 在开始前写入完整计划，执行中及每例结束原子更新，`report.json` 可重算。瞬时模型/网络失败只在恢复本角色文件检查点后自动重试一次，每次失败分类/hash/未知用量进入state.faults；持续失败原生暂停，批次中计为失败并保留恢复入口，不替评测结果人工接续。不会自动换模型或用fixture回填同一Run。

人工在 `trials.json` 的 review 中填写身份标签、六维评分和各维依据、硬失败与高风险缺陷；源码、plan、work、history和检查报告均在对应trial可追溯。必须引用具体证据，不得由被评Agent填写或只依据隐藏通过赋满分。`admission` 维持 null，最终准入由负责人检查完整计划、重复次数、关键案例与量表后明确决定；自动脚本不提供生产授权。

## 实测边界

执行 Adapter 使用 Mastra 原生 LocalFilesystem 和 LocalSandbox。macOS 使用自定义 Seatbelt 限制候选以外的文件内容/目录枚举、禁止网络、只允许独占临时目录写入，不继承宿主密钥环境；Linux bwrap 路径存在但本机未验。Node 测试使用隔离 worker，并要求 TAP 中存在具名用例记录；候选模块加载时直接退出不能伪造宿主 TAP 汇总或空跑通过。检查进程30秒、V8 heap128MiB、日志每流16KiB。这些不等于完整 CPU/RSS/PID 配额，也不保证能对抗主动篡改运行环境或恶意进程逃逸。此入口用于受控离线开发试点；外部不可信项目需重新评估容器/远程沙箱及资源配额。
