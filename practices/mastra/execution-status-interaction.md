# 长时间执行、重试与恢复交互设计

版本：2026-11-10。状态：首批交互已实现；其余条目标注为后续设计。当前参数见[实际配置](config/README.md#超时与重试的实际配置)。本文不修改已有Run、批准或运行策略。

## 1. 当前问题

Run 0b11026e-70da-4c69-9f64-f47a892cb79d 的需求梳理两次收到HTTP 524，分别耗时585.1秒、726.7秒，约21分52秒后失败。5轮确认及总产品产物保留，后续角色未执行。运行中页面只有累计耗时，没有显示首次失败和第二次重试；失败明细要等整个角色结束后汇总。

目标是解释当前工作、最近实际活动、尝试次数、有效限制及可用处理。累计等待不是完成百分比，未收到事件不能自动判定卡死。

## 2. 场景、提示与操作

| 场景及依据 | 展示内容 | 操作及影响 | 当前状态 |
| --- | --- | --- | --- |
| 原生Run running但没有细分事件 | 当前阶段执行中；细分活动未采集 | 刷新状态、查看已完成成果；不重新执行 | 已有刷新，产品进度说明缺失 |
| 成功读取已登记资料 | 正在核对资料；最近读取时间及次数 | 查看非敏感资料目录；次数不代表需求完成度 | 拟新增 |
| 已派发模型步骤，尚未返回 | 等待模型响应；当前步骤耗时 | 继续等待即维持当前调用；查看有效配置，不新建请求 | 拟新增 |
| 观察或反思有开始事件 | 正在整理上下文，可能增加模型调用 | 查看开始及结束时间；未结束不能称完成 | 拟新增 |
| 流式内容到达 | 正在生成；最近内容时间 | 可评估只读预览；未通过结束校验不得批准 | 写作已用stream，前端预览未实现 |
| 临时错误后将自动重试 | 首次HTTP524及实际耗时；准备/执行第2次，共2次 | 展开历史与重试范围；禁止同时手工重试 | 自动重试已有，实时展示拟新增 |
| 写连接504，原Run running | 页面连接超时，后台仍执行，正在回读 | 查看状态或稍后回来；禁止重发批准 | 已有回读机制 |
| GET不可达 | 后台状态暂时未知；最后确认时间 | 重新查询；不补发写操作，不宣称执行失败 | 已有未知态保护，展示拟细化 |
| 角色明确failed，恢复令牌有效 | 失败来源、尝试历史、保留成果及未执行阶段 | 从失败角色重试；重做该角色及后续，保留成功前序，可能增加费用 | 已有产品恢复 |
| 连续两次相同524 | 原样重试仍可能再次失败 | 查看上游/输出方式/资料处理建议；配置调整须单独预检 | 拟新增建议与预检 |
| 输出截断/工具耗尽/格式无效 | 按真实错误说明，不称为网络超时 | 先核查输出或工具策略，再合法恢复 | 已有部分分类，细化交互拟新增 |
| 产物生成后同步失败 | 结果已保存，失败在远端同步 | 只重试同步，不调用模型 | 已有受限入口 |
| 开发累计调用预算用完 | 显示N/M次及检查点 | 已有追加额度表单；不清零累计，不扩业务权限 | 已有，仅开发登记关口 |

关闭页面不暂停执行。无新事件只能显示“最近N分钟未取得新记录”，不能据此推断上游排队、断网或模型停止。心跳只证明进程可达，不证明业务推进。

## 3. 卡片与尝试时间线

运行卡片固定显示阶段、状态、阶段累计耗时、当前尝试序号及耗时、最近实际活动、后续未执行阶段。详情分开显示已完成尝试的原因、HTTP码、实际耗时和下一次开始时间。累计尝试包含工具读取和上下文整理，不等同单次上游请求时长。

本页等待、阶段累计、尝试耗时、模型步骤等待分别计时。阶段时间来自服务端，刷新不归零。缺少事件的分项显示“未采集”。不显示虚构ETA或百分比。

配置详情显示角色模型、配置版本/散列、单步时限、共享总时限、最大尝试及隐式重试设置。历史Run未冻结参数时注明“当前代码默认值，未证明为该Run配置”，不能补写历史事实。

示例：需求梳理执行失败；第一次9分45秒、第二次12分7秒，均HTTP524。总产品已完成，闭环与写作未执行。“从需求梳理重试”旁说明重新读取资料并生成，不是从已有token续写。

## 4. 按场景调整策略

| 场景 | 推荐处理 | 影响及限制 |
| --- | --- | --- |
| 偶发网络、429、5xx | 保留有界重试和退避；核对上游限流及Retry-After支持 | 增加调用等待，不保证恢复 |
| 连续524 | 核对上游时限；评估只读产品角色使用stream及结束校验 | 增大stepMs不能改变上游限制；流式也须真实验证，不能保证无524 |
| 重复读长历史、频繁观察 | 最小确认规则交接配合原文引用，复用可验证的已读取信息 | 不删确认规则，不凭字符数推token窗口；观察阈值调整需质量证据 |
| 输出上限 | 分章节生成并版本绑定，或明确调整输出额度 | 不能静默删需求，部分稿不得发布为完整稿 |
| 工具步数耗尽 | 检查重复加载、工具错误及最终提交预留 | 加时间不能消除步数上限 |
| 浏览器超时 | 固定Run ID并回读 | 加长连接不加快模型，禁止重复提交 |
| 仅同步失败 | 使用同步恢复 | 复用生成结果，仍校验版本权限 |

新策略候选：自动重试一次（当前行为）、首次临时错误后询问、连续同类故障后提示先排障。这些策略选项尚未上线；不新增澄清总轮数或费用门槛，不因等待长自动缩减业务。

## 5. 恢复、配置修改与取消

第一批提供只读有效配置和尝试详情，不开放任意参数。第二批在合法失败检查点提供“沿用原配置重试”和“查看并申请调整”，列出旧新值、适用角色、重做范围、保留成果、费用和版本影响。重试沿用现有令牌；配置调整必须经服务端白名单与版本预检，记录新的恢复调用配置，不覆盖旧尝试。

模型、方法、输入和权限变化可能触发当前身份校验。当前不支持的调整明确拒绝并解释新Run关联方式，不能直接承诺切模型在原检查点继续。正文变更仍需产品批准，扩大执行权限仍需方案授权。

当前已对本机活动需求分析和四产品角色提供二次确认取消，原生取消结合实际AbortSignal传递，退避期间立即中止，迟到结果禁止交付。开发、同步和发布等副作用阶段不开放取消；上游是否停止计算及计费不作保证。状态必须经过取消请求、取消中、确认已停止；确认前禁止重试。浏览器取消等待不是取消Workflow，服务重启不是用户暂停。

“下次失败后询问”需持久化策略，仅影响未派发重试；派发竞争时以版本校验拒绝过期设置。不能用按钮文字掩盖没有实际中断能力。

## 6. 技术边界与落地顺序

复用Mastra原生Workflow、Store、回调和现有Time travel；不创建第二审批或恢复库。先核实锁定版本能否保存及查询运行中元数据/事件。诊断可以丢失但不得影响审批和恢复；进程Map、浏览器计时不能作为权威运行状态。

诊断最小字段：runId、stepPath、invocationId、attempt、sequence、事件类型、服务端时间、配置版本、步骤序号、白名单失败来源及HTTP码。按调用顺序去重，隔离Run和恢复调用。原始prompt、模型正文、密钥、URL和错误HTML不进入诊断展示；若实现生成预览须单独处理权限。

A：只读诊断与配置。补产品节点、尝试事件及上下文整理显示；写入等待期间独立GET，不必等180秒连接结束才观察。

B：按失败原因提供合法恢复与配置预检，连续同类错误说明原样重试风险。

C：验证取消、恢复竞争及策略变更，再开放运行中操作。

当前实现保留原生Run终态与恢复令牌，不将旧消息补成实时事件。细粒度观察在进程内有界保存（最多200条），不是审批或恢复事实源；服务重启缺失记录明确说明。在线配置调整、资料读取/观察记忆/流式内容事件、跨实例取消仍未实现。

## 7. 验收场景

| 场景 | 预期 |
| --- | --- |
| 首次524后第二次运行 | 首次失败立即显示，不等第二次结束；两次计时独立 |
| 两次524最终失败 | 明细齐全、成功前序保留、恢复入口合法、下游未执行 |
| 运行中刷新 | 尝试状态和阶段时长保留；缺字段显示未采集 |
| 写连接504但Run running | 一次写入，持续GET，不出现手工重试按钮 |
| GET暂时失败后恢复 | 未知态不重发批准，恢复后以原Run状态为准 |
| 事件乱序或跨Run | 旧尝试不覆盖新尝试，不混数据，诊断不授予批准 |
| 整理上下文慢或失败 | 开始结束有证据，未完整正文不发布 |
| 截断/工具耗尽/同步失败 | 分类及处理各自对应，不统一称超时 |
| 重复恢复、旧令牌、模型漂移 | 服务端拒绝，无并发模型执行 |
| 取消与完成竞争 | 以原生终态仲裁；确认前不称已停止，迟到结果不得放行 |
| 历史Run缺少详情 | 明示未采集，不根据累计耗时猜尝试次数 |

## 8. 首批实现与验证（2026-11-10）

- 写请求等待期间每5秒独立回读；GET失败显示状态未知，不补发写入。
- 当前角色、尝试序号、两个独立服务端计时、真实模型步骤数、最近活动及脱敏失败历史。需求分析最多1次，四产品角色最多2次。页面仅展示模型步骤完成事件，不声称观察到内部反思或资料读取。
- POST `/intake-api/runs/:runId/cancel` 要求同源和本次调用UUID令牌；不受start/respond长锁阻塞。非本机、旧令牌、已结束调用拒绝；重复请求幂等。
- 原生终态可能先变canceled；调用退出前页面仍显示取消中。取消后的Run不提供原位恢复，保留已保存回答和成果。
- 取消明细是易失观察；历史Run继续使用既有持久失败证据和合法恢复，不推断其当前代码配置。

回归入口：`npm run check`、`npm run review:build`、`npx tsx --test tests/execution-control.test.ts tests/product-generation.test.ts tests/product-skill-evaluation.test.ts`。覆盖真实Mastra/LibSQL嵌套取消、长HTTP锁、来源限制、迟到结果、退避取消、旧令牌和计量回调兼容。浏览器以隔离API合成状态验证交互，不调用业务模型或更改原业务Run。

浏览器回归可复跑：先启动4112前端，再执行 `node scripts/verify-execution-ui.mjs`，仅拦截合成API，不操作真实Run。2026-11-10首次全量回归暴露默认计量回调覆盖及精简测试Agent兼容问题，均已修复；26项定向回归通过。另一本机交付健康失败用例在并行全量中返回blocked，独立重跑8项全部通过，不将此现象隐去。
