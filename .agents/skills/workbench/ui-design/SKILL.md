# 工作台 UI 设计与交互

用于 `web/` 工作台界面的设计、实现和体验审查。以真实用户任务和当前项目界面为依据，形成一致、易理解、可操作的界面；不要把示例、原型或本 Skill 当作已经实现的设计系统。

## 开始前

- 阅读项目协作规则和相关稳定契约，检查工作区变更；沿目标页面查看组件、样式、数据来源和已有相似交互。尊重用户已有设计和未提交修改。
- 先识别用户、操作目标、信息归属、主要路径及必要的加载、空、错误和成功状态。信息来源或作用范围不同的内容应清晰区分；团队专属设置归团队，共享信息独立展示。
- 从 `web/package.json`、现有组件和样式确认实际技术栈与设计约定；当前约定可能随项目变化，不假定已安装完整组件库。优先复用已有组件、图标和样式变量；重复模式确有使用方时再提取公共组件。

## 设计与实现

- 围绕工作台任务确定布局层级、阅读顺序和主要操作，延续现有品牌与已确认的视觉方向。为相关页面统一间距、字号、颜色、边框、表单和按钮状态，避免为装饰而增加卡片或动效。
- 确保按钮含义、当前选中项、字段标签和单位明确；配置页面展示权威来源、当前值、保存反馈和实际生效范围。禁用原因及错误应可理解，不把只读值伪装成可编辑项。
- 处理未登录、加载、空值、校验失败、保存中、失败及成功等适用状态。编辑多个独立配置时，保存范围必须与页面表达一致，避免意外覆盖其他未提交内容。
- 使用语义化 HTML，支持键盘操作、可见焦点、清晰标签和错误关联；对话框管理焦点与关闭操作。适配桌面和窄屏，考虑文本缩放、对比度和减少动态效果的系统偏好。
- 区分视觉调整与行为契约变更：改变权限、保存、生效或流程语义时先核对并更新适用 OpenSpec；不为样式任务擅自修改业务规则、审批或配置来源。
- 引入组件库、字体或其他依赖前，评估项目现有技术栈、许可、包体与维护成本；依据用户授权和项目既有决策实施，不声称已建立尚未落地的规范。

## 已验证的试点约定

- 团队配置页是独立页面，不能依赖 `.intake-shell` 下的按钮样式；页面容器自身提供按钮、输入框和键盘焦点样式，并与账号弹窗沿用现有品牌强调色。
- 账号弹窗使用原生 `dialog` 和独立挂载位置，避免父页面卡片样式影响居中；保留可见标题、字段标签和关闭入口。浏览器已检查打开、默认焦点与 Escape 关闭。
- 配置页区分团队区域和平台共用区域；未登录时保留清晰的返回入口与错误提示。隔离模拟接口下已检查团队切换、模型保存回读、跨团队草稿保留及 390px 布局；真实登录、真实服务保存和辅助技术表现仍须单独验证。

## 验证与交付

- 按改动范围运行前端类型检查和构建；对于交互或布局改动，在可用环境中检查实际页面，覆盖主要操作、相关状态、键盘和适用的窄屏布局。不可用时说明阻塞，不把构建成功当成视觉验收。
- 审查任务先报告具体问题、影响及代码位置；实现任务说明实际修改、验证结果和未验证范围。正式浏览器 QA 按项目 `testing/gstack-browser-qa` 的批准用例和证据边界执行。
- 如外部视觉设计或无障碍 Skill 已安装且适合当前任务，可结合使用；外部建议与项目事实、用户要求或现有契约冲突时，以后者为准。本 Skill 不授予发布、部署或远端操作权限。
