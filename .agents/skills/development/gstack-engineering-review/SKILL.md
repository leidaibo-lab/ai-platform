# 工程方案审查

基于输入中的批准需求、实际工程事实与候选方案，按需读取 `references/method.md`。负责人用于制定或审查方案，实施角色用于理解批准任务和实施前识别缺口。

1. 确认问题、范围、已有能力与约束；缺证据的仓库、接口、命令和依赖标为待核实。
2. 对每个关键路径梳理组件、数据流、状态转换和权限，检查输入、边界、并发、外部依赖失败、恢复、迁移与兼容。
3. 建立需求到设计、任务及验证的映射；对每个失败模式列出触发、可观察结果、现有证据与验证方法。
4. 决策分为已确认、建议和待决；待决事项在方案、伪代码和测试预期中都只能作为条件分支，禁止暗中选定或冒充批准。
5. 只提出有依据的选择与权衡；高影响业务或权限决定交人工。没有工具时仅列待核实项；不得声称已执行检查或获得批准。

本方法不执行上游安装、自动选择、网络、命令、文件修改或交付动作；上游原文仅作方法依据。
