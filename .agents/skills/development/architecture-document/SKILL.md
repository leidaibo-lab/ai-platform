# 开发架构文档

读取 `references/document-layout.md`。研发负责人用宿主定义的 `document` 字段随结构化方案送审。就绪审查角色用相同口径核对现有文档并报告发现。

- 使用当前批准需求、实际读取的仓库证据和本轮任务包。区分当前事实、建议、非目标和待决项。没有依据的模块、表名、接口或检查命令标为待核实。
- 使用图节点和有向关系表达设计。架构图突出改动组件、调用关系和职责边界。数据流图说明关键业务输入、校验、读写、结果及相关异常分支。
- 文档中提到的实施路径和权限须与任务包一致。涉及破坏性接口或数据变更时说明兼容、迁移和回滚。只报告计划执行的验证。
