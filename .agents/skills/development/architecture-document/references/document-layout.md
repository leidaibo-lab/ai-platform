# 送审口径

## 正文

| 字段 | 内容 |
| --- | --- |
| `scope` | 目标、非目标、批准需求引用与关键工程依据 |
| `impact` | 受影响的模块、路径、上下游、接口、数据、权限、配置与部署。标注变化及影响，按需说明无变化项 |
| `design` | 设计决策及依据、接口契约、数据归属、兼容与迁移方式 |
| `implementation` | 实施顺序与需求到任务的关联。引用已登记检查并说明正常、边界和异常场景的预期 |
| `risks` | 风险、影响、缓解与回滚条件，列出需要人工确认的决策 |

正文使用短段、列表和表格。宿主生成图源与标题。字段内使用普通 Markdown。

## 图

`architecture` 和 `dataFlow` 分别包含 `nodes: [{id,label}]` 和 `edges: [{from,to,label}]`。ID 使用稳定 ASCII 标识。标签使用简明文字、数字和空格。各边必须有语义标签。图规模按本次变更控制，优先展示需要审批的边界和数据变化。

- 架构图标明新增或变更的组件、调用方向、数据所有者和相关外部边界。
- 数据流图用业务数据名称标注箭头。重点展示入口、校验、处理、存储或出站、结果和相关失败分支。纯本地变更说明数据的输入和输出。

## 独立审查

逐项核对正文、两张图、批准需求、仓库事实与任务包是否一致。关注未经授权路径、图中未列出的外部读写、图与契约矛盾、数据迁移或失败分支缺失。沿现有就绪评估输出带需求或任务引用的发现。内容不足时说明妨碍开工的具体后果。
