# 架构与方案决策

本 Skill 将架构决策记录（ADR）作为“为什么这样选”的可执行协作依据，但不把 ADR 当作稳定接口契约。项目分工如下：

- `docs/decisions/` 记录问题、候选、证据、选择、未采用原因、实施边界和重评条件。
- `openspec/` 固化代理行为、Session/Run API、配置、安全和其他稳定契约。
- `docs/` 说明架构、运行边界和演进方式。
- `.agents/skills/` 提供可复用的 Agent 工作流程。

## 何时使用

遇到以下情况时，先使用本 Skill 再进入正式实现：

- 新增或替换平台级、跨模块公共能力、重要依赖、基础设施或架构模式。
- 改变 API、配置、安全边界、数据所有权、Runtime 主链或服务拆分方式。
- 需要在成熟一体化、轻量可组合和最小自研路线之间做真实取舍。
- 发现实现与已接受决策冲突，或需要接受、拒绝、替代、废弃已有决策。

以下情况通常不新建决策：局部缺陷修复、文案/样式修改、既有稳定方案内的等价实现。若影响稳定契约或公共行为，仍需检查 OpenSpec 和现有决策。

## 创建流程

### 阶段 0：扫描仓库

先读取 `docs/decisions/README.md`、相关决策全文、`docs/solution-selection-governance.md`、技术栈入口和目标代码。检索 `ADR:`、决策路径和替代关系，确认目录、文件名、状态和模板约定。不要打印或读取 `.env` 中的真实密钥。

### 阶段 1：澄清意图

根据扫描结果逐步提问，问题一次一个；上下文已经明确的内容不要重复询问。至少确认：

1. 具体决定和“为什么现在决定”。标题使用动词短语。
2. 业务目标、成功证据、硬约束和明确非目标。
3. 至少两类真实候选；默认检查成熟一体化、轻量可组合、最小自研三条路线。不足三类时记录检索范围和原因。
4. 当前倾向、关键权衡、最坏结果、维护责任和退出路径。
5. 受影响的具体文件/目录、应遵循和应避免的既有模式、测试与验证命令。

在起草前给出意图摘要，并等待用户确认或修正：标题、触发、约束、候选、倾向、非目标、相关决策/代码、受影响路径和验证方式。没有确认时不要进入起草阶段；若用户已明确授权且事实足够完整，可把确认作为交付前的显式摘要而非重复打断。

### 阶段 2：起草决策

沿用 `docs/decisions/TEMPLATE.md` 和现有 `YYYY-MM-DD-<slug>.md` 命名。每个决策必须填入真实内容，不保留占位符。至少包含：问题、约束与非目标、候选与证据、淘汰条件、关键验证、决策、未采用方案、实施边界、风险与退出路径、验收与完成报告。

补充 Agent 可执行信息：

- 明确具体版本、依赖、配置和数据所有者。
- 在“实施边界”中列出受影响文件、Port/Adapter、失败语义、迁移步骤、应遵循/避免的模式。
- 在“验收与完成报告”中使用可执行复选框，分别覆盖功能结果、架构边界、文档/契约同步和剩余限制。
- 结论只能是“采用 / 适配 / 自研”，并写清平台拥有与外部方案负责的范围。

没有接受状态的决策，只能做有时间边界的调研或 PoC，不能宣称正式能力完成。

### 阶段 3：审查与交付

用以下问题审查，输出通过项、缺口和修复建议：

- 问题是否描述损耗和成功证据，而不是方案宣传？
- 是否有真实候选、证据和未采用原因？
- 约束、非目标、风险、维护责任和重评条件是否明确？
- 实施计划是否能让另一个 Agent 找到具体文件、配置、模式和测试？
- 验收是否可运行或可人工核对，且覆盖结构边界？
- 是否需要同步 OpenSpec、架构文档、决策索引或评测 fixture？

缺口未修复前不要把决策标为接受，除非用户明确接受这些缺口。接受后把实施计划和后续项转成可追踪任务，在关键代码入口用一条轻量 `ADR: <路径>` 注释建立反向链接；不要在每行代码重复引用。

## 查阅与生命周期

实施架构相关变更前，先读相关“接受”决策的全文，尤其是实施边界、验证和重评条件。与现有决策冲突时，先提出新决策并链接旧记录；不要静默覆盖历史。

- 接受/拒绝：更新状态并保留最终上下文。
- 废弃：说明不再适用的原因和替代路径。
- 替代：新建记录，旧记录标记“已替代”，两边互相链接。
- 新证据：在“更多信息”或验收部分追加日期和证据，不重写历史理由。
- 更新 `docs/decisions/README.md`，保持状态和结论摘要一致。

## 与项目 Skill 的协作

- 新增或修改任何 Skill 时，先遵循 `company-public-skill-governance`，最后运行其校验脚本。
- 涉及上下文、记忆、Prompt 或评测策略时，调用 `docs-context-memory-evaluation`；区分确定性回归和真实模型评测。
- 方案选型必须遵守 `docs/solution-selection-governance.md` 的采用优先、证据、退出路径和完成定义。
- 决策改变稳定行为、接口、配置或安全边界时，先更新对应 OpenSpec，再实现。
